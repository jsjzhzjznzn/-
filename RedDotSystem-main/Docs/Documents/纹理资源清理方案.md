# 纹理资源清理方案（2026-10-22）

## 背景

PerfAgent 在 zhuye 场景的采集报告里给出「纹理内存估算 590 MB，超过预算 512 MB」。
为确认这 590 MB 到底是什么，用编辑器 API（`AssetImporter.GetAtPath` + `GetSourceTextureWidthAndHeight`）把全工程
2060 张 Texture2D 的导入设置导了一遍，输出 `Library/PerfAudit/texture_all.tsv`（Library 不入库）。

两个必须先说清楚的口径问题：

1. **「估算」不等于运行时占用。** 估算按导入设置把全工程纹理算了一遍；实测 `Profiler.GetAllocatedMemoryForGraphicsDriver`
   与 `Memory/Texture Memory` 序列是 426 MB，且这 426 MB 也含编辑器自身。真正被场景加载的只是一小部分。
2. **PerfAgent 那条「优先处理 Read/Write 开启」在本次不适用。** 全工程 7 张开 Read/Write 的全在 `Packages/` 编辑器目录，
   游戏内一张都没有。652 张「未压缩」听着多，合计只有 26.5 MB（都是小 UI 图，本就该保持未压缩）。

## 附：PerfAgent「纹理内存估算 562 MB」虚高的根因（2026-10-22 补）

清理后面板仍报「估算 562 MB，超预算 512 MB」。排查结论：**这不是工程的问题，是插件取不到纹理尺寸后退化成固定值**。

- 现象：562 MB 与工程内容几乎无关 —— 删掉 186 MB 资源，这个数字只掉了 28 MB。
- 反推：647 张纹理 × 1024² × 0.5 B/px × 1.3333（mipmap）= **561 MB**，与面板的 561.83 MB 对得上。
- 根因：`AssetAuditCollector.GetSourceSize` 通过 `Reflect.TryInvoke` 调 `TextureImporter.GetSourceTextureWidthAndHeight(out int, out int)`。
  该 API 形参是 **byref（out int）**，而 `Reflect.CoerceArgs` 只会对参数做 `Convert.ChangeType` —— byref 目标类型转换必然抛异常，
  `TryInvoke` 返回 false，w/h 保持 0；上层 `AuditTextures` 见 `w <= 0` 就**兜底成 1024×1024**。
  于是估算值 = 纹理张数 × 1024² × bpp，与真实尺寸、真实内容无关。
- 修复：`GetSourceSize` 改为直接调用该 API（Unity 2021.3+ 起为 public），失败再退回 0。
  修完重跑静态审计：**561.83 MB → 272 MB**，超预算结论消失。

口径提醒：修好之后 272 MB 仍偏乐观 —— 它的 bpp 表把「Compressed（默认）」当成 0.5 B/px（BC1），
而 BC7/ASTC 4x4 是 1 B/px。按 1 B/px 复算约 418 MB。真实值取决于每张纹理最终落的压缩格式，
要看准得用 Player 开发构建 + Memory Profiler。
