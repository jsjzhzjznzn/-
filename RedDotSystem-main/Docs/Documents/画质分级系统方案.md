# 画质分级系统方案（Quality System）

> 目标工程：`D:\tuanjieproject\frined\RedDotSystem-main`（Tuanjie 2022.3 / URP 14 派生管线）
> 版本：2026-10-25 v1（待评审）
> 关联文档：`Compete战斗系统与UI框架移植方案.md`、`对话场景重构方案.md`

---

## 0. 结论（TL;DR）

现状**不是画质系统**，只是一个「把 Unity 内置 QualitySettings 档位接了个 ←/› 按钮」的浅封装：6 档全部共用同一个 URP 资产，切档只改了 SRP 根本不读的几个字段，**肉眼无变化**。

本方案要做的是「一套资产一份档」：

1. 把画质收敛为 **3 档（低 / 中 / 高）**，每档一套 `UniversalRenderPipelineAsset`，通过 `QualitySettings` 每档的 `customRenderPipeline` 绑定——这是 URP 下**唯一受支持**的运行时换管线方式；
2. 每档再配一份 `VolumeProfile`（后处理强度/开关）+ 帧率上限 + 纹理/阴影参数，由新增的 `GraphicsQualityService` 统一应用；
3. UI 继续用现有 `SettingsView` 的「画质 ←/›」行，只换数据源；面板预制体必须走 `Tools/UI/重建设置面板` 重新生成，**不手改 prefab**；
4. 相机后处理开关收口到 service，场景作者不再各自设 `m_RenderPostProcessing`。

不动架构、不动 `GameSettings` 的对外 API 语义、不动已有 6 个档位槽的序列化结构（方案 A，见 §6）。

## 1. 现状盘点（全部有据可查）

### 1.1 代码链路

| 位置 | 现状 |
|---|---|
| `Assets/Game/Scripts/UI/Settings/GameSettings.cs` | `QualityLevel`（PlayerPrefs `settings_quality`）→ `QualitySettings.SetQualityLevel(level, true)`；`[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` 启动自动 `Load()+Apply()`；`Changed` 事件通知 UI |
| `Assets/Game/Scripts/UI/Settings/SettingsView.cs` | 画质行 = `qualityText` + `qualityPrevButton`/`qualityNextButton`，文案 `{QualityName}（{Level+1}/{Count}）`（:160），点击走 `GameSettings.CycleQuality(±1)` |
| `Assets/Game/Scripts/UI/Settings/Editor/SettingsPrefabBuilder.cs` | 面板预制体由 `Tools/UI/重建设置面板` 全量生成，输出 `Assets/Game/UI/Settings/SettingsView.prefab`；控件靠 `[ControlBinding]` + `Bind(data, "qualityText", …)` 绑定 |
| 全工程其它 `QualitySettings` 用法 | 只有 `Assets/PerfAgent/**`（性能分析工具读取上报，无写入）→ **改档位索引不会影响别处** |

### 1.2 引擎侧配置

- `ProjectSettings/QualitySettings.asset`：6 档 `Very Low / Low / Medium / High / Very High / Ultra`，`m_CurrentQuality: 5`，`m_PerPlatformDefaultQuality: {}`（无平台默认）。
- **6 档的 `customRenderPipeline` 全部是 `{fileID: 0}`** → 全部回落到 `GraphicsSettings.asset` 的全局 `m_CustomRenderPipeline = URP-PipelineAsset`。
- `Assets/Game/Settings/URP-PipelineAsset.asset`（全档共用）：`m_RenderScale: 1`、`m_MSAA: 1`（关）、`m_SupportsHDR: 1`、`m_MainLightShadowmapResolution: 2048`、`m_AdditionalLightsPerObjectLimit: 4`、`m_AdditionalLightShadowsSupported: 0`、`m_ShadowDistance: 50`、`m_ShadowCascadeCount: 1`、`m_SoftShadowsSupported: 0`、SRP Batcher 开、`m_UseAdaptivePerformance: 1`；资产里已带 Tuanjie 的 FSR / TJSR / DLSS / MetalFX 升级字段。
- `Assets/Game/Settings/URP-ForwardRenderer.asset`：`m_RendererFeatures: []`（无 SSAO/Decal 等）、`postProcessData` 已正确指向（非空）、`m_UseNativeRenderPass: 0`。

### 1.3 现有 6 档的实际差异与为何无效

| 字段 | Very Low | Low | Medium | High | Very High | Ultra | SRP 下是否生效 |
|---|---|---|---|---|---|---|---|
| `pixelLightCount` | 0 | 0 | 1 | 2 | 3 | 4 | 否，URP 用资产里的 per-object limit |
| `shadows` | 0 | 0 | 1 | 2 | 2 | 2 | 否，URP 看资产 + 灯光 |
| `shadowDistance` | 15 | 20 | 20 | 40 | 70 | 150 | **否**，被资产 `m_ShadowDistance: 50` 覆盖 |
| `antiAliasing` | 0 | 0 | 0 | 0 | 2 | 0 | 否，URP 用 `m_MSAA` |
| `lodBias` | 0.3 | 0.4 | 0.7 | 1 | 1.5 | 2 | 是 |
| `textureQuality` / 各向异性 | 低 | 低 | 中 | 中 | 高 | 高 | 是 |
| `vSyncCount` | 0 | 0 | 1 | 1 | 1 | 1 | 是 |
| `customRenderPipeline` | 0 | 0 | 0 | 0 | 0 | 0 | — |

结论：玩家点「画质 +」时，真实变化只有 LOD bias / 各向异性 / 纹理质量 / VSync —— 这三项在一部 1920×1080 的 PC 上几乎不可感知。

### 1.4 后处理分布（不统一）

| 场景 | 相机 `m_RenderPostProcessing` | Volume |
|---|---|---|
| `duihua.scene` | 1（`m_Antialiasing: 2` = SMAA） | `PostFX_Volume` |
| `multiplecompete.scene` | **0** | `Global Volume`（profile = `SampleSceneProfile`） |
| `tiaozhan / fuben / gas / zhuye / LOGIN / 111` | 0 | 无 |

即：战斗场景挂了 Volume 却把相机的后处理关了 → `SampleSceneProfile`（Bloom / Vignette / Tonemapping / MotionBlur）实际不生效。这是一处**既有不一致**，本方案会顺手收口（§5.4），但会改变战斗场景观感，需美术确认（见 §9 风险 3）。

## 2. 设计原则

1. **一份档位 = 一份资产**。不运行时改 `UniversalRenderPipelineAsset` 字段：它是 ScriptableObject，改了会脏化资产、编辑器下永久生效、且不重建 URP 内部资源（`RenderScale` 之类需要重建 RT），属于隐性坑。
2. **换档唯一入口是 `QualitySettings.SetQualityLevel`**。URP 不支持运行时替换 `GraphicsSettings.renderPipelineAsset`，但支持每档 `customRenderPipeline`，切档即重建管线。
3. **只暴露玩家可感知的旋钮**。分辨率/窗口模式/DLSS 这类本期不做（§8）。
4. **UI 与资产生成可重放**。凡是预制体/资产，都要有编辑器脚本一键生成，禁止手改（沿用工程现有 `Tools/UI/重建设置面板` 的惯例）。
5. **不破坏既有持久化**：`settings_quality` 里已存的 int 继续可读（clamp 到新档数）。

基准 = 当前资产（High 档即现状，保证不改高端观感）。

| 参数（URP 资产字段） | 低 | 中 | 高（现状 + 表中提升项） |

| `m_ShadowCascadeCount` | 1 | 2 | 2 |
| `m_SoftShadowsSupported` | 0 | 0 | 1 |
| `m_AdditionalLightsRenderingMode` | 1（PerPixel；2026-10-26 由「关」改为保留，见 §13.1） | 1（PerPixel） | 1 |
| `m_AdditionalLightsPerObjectLimit` | 2 | 2 | 4 |
| `m_AdditionalLightShadowsSupported` | 0 | 0 | 0 |
| 相机 AA（`m_Antialiasing`） | 0（关） | 0 | 2（SMAA，仅 `duihua` 现状如此） |
| 后处理 | 仅 Tonemapping | + Bloom / Vignette | 全开（+ DoF / MotionBlur 按场景 profile） |
| 纹理 mipmap limit | 0（不动） | 0 | 0 |

> Tuanjie 的 TJSR/FSR 走 `m_TJSRSettings` / `m_UpscalingFilter`，移动端 GLES 不支持，需运行时按 `SystemInfo` 判断可用性。

## 4. 资产清单（新增，不动旧文件）

```
Assets/Game/Settings/Quality/
├─ URP-PipelineAsset_Low.asset        # 由现有 URP-PipelineAsset 复制后改字段
├─ URP-PipelineAsset_Medium.asset
├─ URP-PipelineAsset_High.asset       # = 现有参数快照

└─ GraphicsQualitySettings.asset      # 运行时配置（Resources 加载，BeforeSceneLoad 就要读）
```

## 5. 代码设计

### 5.1 新增 `GraphicsQualitySettings`（SO：档位表）

```csharp
public enum QualityTier { Low = 0, Medium = 1, High = 2 }

[CreateAssetMenu(menuName = "Game/Graphics Quality Settings")]
public class GraphicsQualitySettings : ScriptableObject
{
    [Serializable] public class Tier
    {
        public QualityTier tier;
        public string displayName;            // "低" / "中" / "高"
        public int qualityLevelIndex;         // 对应 ProjectSettings 里的档位索引（方案 A：1 / 3 / 5）
        public UniversalRenderPipelineAsset pipeline;
        public VolumeProfile postFx;
        public bool postProcessingEnabled;
        public int targetFrameRate;           // 0 = 不限制
        public int cameraAntialiasing;        // 0=None 1=FXAA 2=SMAA
    }
    public List<Tier> tiers;
    public Tier Find(QualityTier t);
}
```
放在 `Assets/Game/Resources/Quality/GraphicsQualitySettings.asset`（或由 service 序列化引用），避免运行时 `Resources.Load` 之外的定位问题。

### 5.2 新增 `GraphicsQualityService`（静态，仿 `GameSettings` 风格）

职责（唯一写入口）：

```csharp
public static class GraphicsQualityService
{
    public static QualityTier Current { get; }
    public static void Apply(QualityTier tier);      // 全量应用
    public static void ApplyToActiveScene();          // 场景加载后补一次（相机/Volume）
    public static event Action Applied;
}
```

`Apply` 做的事，顺序固定：

1. `QualitySettings.SetQualityLevel(index, applyExpensiveChanges: true)` → 重建 URP 管线（一次性 hiccup，见 §9-1）；
2. `Application.targetFrameRate = tier.targetFrameRate`；
3. 遍历 `Camera.allCameras`（含未激活需 `FindObjectsOfType<Camera>(true)`）：`GetUniversalAdditionalCameraData().renderPostProcessing = postProcessingEnabled`，`antialiasing`/`antialiasingQuality` 按档写；
4. 遍历 `Volume`（`isGlobal`）：`sharedProfile = tier.postFx`；
5. `GraphicsQualitySettings` 里 `lodBias` 之类若需覆盖也在此写（`QualitySettings.lodBias`）。

> `Apply` 必须先 `GameSettings.Apply()` 里的音量部分互不干扰；`GameSettings.Apply` 里保留 `SetQualityLevel` 调用会与本服务重复 → 统一改为 `GameSettings` 调 `GraphicsQualityService.Apply`（§5.3）。

### 5.3 `GameSettings` 最小改动

- 新增 `public static QualityTier Tier { get; }`、`public static string TierName`、`public static int TierCount => 3`；
- `QualityLevel`（原始索引）保留，仅供内部 `SetQualityLevel`；
- `Load()`：读 `settings_quality`（存的是 **tier 0..2**），旧存档里若存的是 0..5 的旧索引，按 `Mathf.Clamp(raw, 0, 2)` 兼容（旧值 3~5 会落到「高」，属可接受的降级）；
- `Apply()`：把 `SetQualityLevel` 一行替换为 `GraphicsQualityService.Apply(Tier)`；
- `CycleQuality(±1)` 改为在 3 档间循环；`QualityName` 改为取 `Tier.displayName`。

> 之所以存 tier 而不存引擎索引：引擎档位以后再加/删都不会影响玩家存档语义。

### 5.4 后处理与相机收口

实装（P4）采用**权重缩放**，不替换 profile：

| 档 | `postProcessingEnabled` | `postFxWeight` | `cameraAntialiasing` |
|---|---|---|---|
| 低 | false | 0 | 0（关） |
| 中 | true | 0.75 | 0 |
| 高 | true | 1.0 | 2（SMAA） |

- `ApplyToActiveScene()` 遍历场景里的 `Volume`（只认 `isGlobal`）：`volume.weight = postFxWeight`；
  遍历 `Camera`（只认 `cameraType == Game`）：`renderPostProcessing = postProcessingEnabled`，`antialiasing` 按档写。
- **只在 Play 模式生效**：编辑器里改 `Volume.weight` / 相机字段会把值写进场景资产，所以编辑器内的画质预览只看 URP 资产（P2），要看后处理差异请进 Play。
- **只接管有 Global Volume 的场景**（`duihua` / `multiplecompete`）；`zhuye / tiaozhan / fuben / gas / LOGIN` 没有 Volume，相机设置保持美术原样，不被一刀切。
- 副作用（需美术确认）：`multiplecompete` 从「有 Volume 但不生效」变成中/高档生效（§9-3）；`duihua` 在低档会丢 Bloom/Vignette（权重 0）。
- 挂接点：`GraphicsQualityService` 在首次 `Apply` 时订阅 `SceneManager.sceneLoaded`，所以每次进场景都会按当前档位重刷一遍。

### 5.5 UI（复用现有面板，仅加一行）

- `SettingsView`：`qualityText` 文案改 `{TierName}（{Tier+1}/{TierCount}）`；点击仍走 `CycleQuality`。
- 新增一行「渲染比例」（可选，P5）：`renderScaleSlider` + `renderScaleValueText`，3 档预设值 0.75/0.9/1.0，**不提供自由拖动**（URP 的 renderScale 是资产级，自由拖动会退化成本方案要避免的运行时改资产）。
  - 若不接受「资产级」，本期就不做这一行（推荐先不做，§8）。
- 面板布局是绝对坐标（`TopLeft(x, y, w, h)`），加行需要把底部按钮整体下移：面板高 640 → 700，或在「画面」区压缩行距。改完必须跑 `Tools/UI/重建设置面板` 重新生成 prefab 与 `UIControlData` 绑定。

### 5.6 编辑器工具（`Assets/Game/Scripts/UI/Settings/Editor/` 或新建 `Game/Editor/Graphics`）

| 菜单 | 作用 |
|---|---|
| `Tools/Graphics/生成三档 URP 资产` | 复制 `URP-PipelineAsset` → `Quality/` 三个资产，用 `SerializedObject` 写 §3 表里的字段（字段是 private serialized，必须走 SerializedObject，不能直接赋值） |

| `Tools/Graphics/校验画质配置` | 断言：每档 `customRenderPipeline` 非空、renderer 非空、`GraphicsQualitySettings.tiers` 三项齐全、场景 Global Volume 存在 → 输出 PASS/FAIL 清单 |

## 6. 档位槽方案（二选一，需拍板）

### 方案 A（推荐）：保留 6 个槽，只重配 3 个
- 用 `1 / 3 / 5` 三个索引（`Low / High / Ultra` 位置）放低/中/高；`0 / 2 / 4` 保留但 UI 不暴露；
- 优点：`QualitySettings.asset` 结构不动，任何按索引取值的旧代码/PerfAgent 口径都不用改；`m_CurrentQuality: 5` 不用动；
- 缺点：`QualitySettings.names` 里仍有 6 个名字，需要把 UI 文案换成 tier 名（§5.3 已含）。

### 方案 B：直接删到 3 档
- 优点：配置干净，Inspector 里不再有僵尸档；
- 缺点：`m_CurrentQuality` 与任何外部脚本的索引假设都要跟着改（已确认全工程只有 `GameSettings` 用索引，风险其实很小），且以后要加「极高」档还得再扩。

> 下文按方案 A 写步骤；选 B 只需把 `qualityLevelIndex` 改成 `0/1/2` 并删掉 3 档。

## 7. 生效时序

```
启动(BeforeSceneLoad)         场景加载完成                 玩家改档
GameSettings.Load()      →    Service.ApplyToActiveScene()  →  Service.Apply(tier)
  ↓                              ↓                              ↓
GraphicsQualityService.Apply 相机 PP / Volume profile 重灌   SetQualityLevel 重建管线
  ↓                                                          + 帧率 + PP + Volume
SetQualityLevel(重建管线)                                      + 写 PlayerPrefs
```

- 启动时重建管线发生在首帧黑屏前，玩家看不到；
- **运行时改档会有一次管线重建卡顿（PC 上 50~150ms，移动端更久）**：UI 上表现为点一下闪一下。可接受则不做处理；不可接受则加「应用」按钮 + 200ms 淡入遮罩（P5 可选）。
- 编辑器里切档会让 Game 视图闪一帧，属正常现象，写进使用说明。

## 8. 本期不做（明确划界）

| 项 | 原因 |
|---|---|
| 分辨率 / 窗口模式 | 现有只有「全屏」开关；改分辨率要处理假全屏与 UI 适配 |
| DLSS / TJSR 手动开关 | Tuanjie 已有字段但平台支持差异大，等 §3 的 FSR/TJSR 方案验证后再做 |
| 纹理 mipmap limit（`globalTextureMipmapLimit`） | 会连带糊掉 UI 图集与 TMP 字体，收益/风险不划算 |
| 逐项自定义（阴影距离滑块等） | 与「一份资产一档」冲突，且玩家认知成本高 |
| 动态分辨率 | 需要 `m_UseAdaptivePerformance` 之外的额外框架，另立项 |

## 9. 风险与对策

1. **切档 hiccup**：管线重建导致 50~150ms 卡顿。对策：设置面板里切档时先播 0.15s 遮罩；或改为「返回主页时应用」。
2. **老存档语义**：`settings_quality` 旧值是 0~5。对策：`Load()` 里 `Clamp(raw, 0, 2)`，并在第一个版本写迁移标记（`settings_quality_v2 = 1`），避免二次误解。
3. **观感变化**：`multiplecompete` 后处理从关变开、阴影距离从固定 50 变 20/35/50。对策：三档的 High 与现状完全一致；低/中档出图给美术确认后再合。
4. **移动端/GLES**：`m_UpscalingFilter` 在 GLES 上无效，`m_MSAA 4` 在低端机有掉帧风险。对策：运行时 `SystemInfo.supports…` 判断，低档强制 `m_MSAA 1`（已如此）。
5. **场景作者与 service 抢相机 PP**：收口后若有人在场景里手改，下次进场景会被覆盖。对策：写进 `UI框架化预制体规范` 一类的规范文档，并在 `GraphicsQualityService` 上加 `[Tooltip]` 说明。
6. **PerfAgent 基线口径**：`Assets/PerfAgent` 会读 `vSyncCount/targetFrameRate` 报「未限帧」。对策：跑基线时固定在高档并记录档位，报告里注明。

## 13. 实施记录（2026-10-26：低档照明 + 玩法场景后处理）

### 13.1 低档保留附加光

`GraphicsQualityAssetBuilder.Tiers` 的低档由「附加光关闭（addMode=0 / perObject=0）」改为 **PerPixel 2 盏/物体**，`URP-PipelineAsset_Low.asset` 已按新参数重新生成（校验菜单三档 PASS）。

- 动机：duihua 大厅照明是 5×Point(55) + DialogueFill(25) + 主光 0.28，低档把附加光整体关掉会丢暖色主光。
- 为什么不用 PerVertex：大厅是大块低模 + ShaderGraph 卡通材质，顶点光照容易出现块状渐变；且卡通图未必编译 `_ADDITIONAL_LIGHTS_VERTEX` 变体（那样效果上等于同样关灯）。
- **修正原判断（重要）**：低档并不会"打成黑屋"。实测把 6 盏点光全部关掉，大厅依旧可见（环境光 Flat 0.15~0.19 + 主光 0.28 兜底），只是整体偏冷、植物发黑。这条改动的价值是"保住设计好的暖色照明"，不是修复崩溃级问题；如果后续更吃性能，可以再把低档降到 PerVertex 做 A/B（先确认卡通 shader 的顶点光变体）。
- 实测（Play，duihua）：低档画面完整可读（地面/沙发/植物/角色都在），与高档的差异是「少 ACES + 少暗角 → 更平更亮」。

### 13.2 fuben / tiaozhan 补轻量 Global Volume

新增 `Assets/Game/Settings/Gameplay_PostFX.asset`（ACES Tonemapping + Bloom：threshold 1.1 / intensity 0.15 / scatter 0.55 + Vignette：0.25 / smoothness 0.4），由菜单 **Tools/Graphics/安装玩法场景后处理（fuben/tiaozhan）**（`Assets/Game/Scripts/Graphics/Editor/GameplayPostFxBuilder.cs`）幂等写入两个场景的 `Global Volume`。

- 强度仍由 `GraphicsQualityService` 用 `Volume.weight` 缩放：低 0（相机 PP 同时关）/ 中 0.75 / 高 1。
- 与 `duihua_PostFX` 分工：那份是叙事调色（白平衡/色相/更重暗角），这份只做统一色彩响应 + 轻微辉光，不覆盖美术打光。
- 实测（Play）：fuben / tiaozhan 均 `pp=True, weight=1`（高）与 `pp=False, weight=0`（低）；高档层次明显好于低档直出。
- 副作用：`multiplecompete` 的 `SampleSceneProfile` 在中/高档也会开始生效（§9-3 的观感变化仍然成立，需美术确认）。

### 13.3 本轮踩到并已规避的两个坑

1. **本工程 URP 分支的 `VolumeProfile.Add<T>()` 不会把组件写成子资产**：`com.unity.render-pipelines.core@14.2.0-t1` 的 `VolumeProfile.Add(Type)` 里 `#if UNITY_EDITOR` 块是空的（标准 URP 会调 `AssetDatabase.AddObjectToAsset`）。结果是 `components` 里留下 3 个 `{fileID: 0}`，运行时 Profile 为空、后处理完全不生效，而 Inspector 上看起来"有组件"。修法：`GetOrAdd<T>` 自己 `CreateInstance` + `HideFlags` + `AssetDatabase.AddObjectToAsset`，并清理 null 条目。以后用代码生成任何 VolumeProfile 都要检查落盘后的 fileID。
2. **Tuanjie URP 下把相机渲到 RT 再 ReadPixels 不可信**：同一帧内改变相机朝向、抬高 6m、甚至关掉全部灯光（含主光），回读的平均亮度与中心像素完全不变（0.1972 / RGB 46,46,50）。视觉验证必须走 Game View 抓帧（`ManageScreenshot` / `record_game_view`），RT 直读只能当"有没有渲染"的粗略信号。
