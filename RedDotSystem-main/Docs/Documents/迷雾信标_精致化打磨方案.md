# 《迷雾信标》精致化打磨方案

> 编写日期：2026-10-27
> 定位：把已经跑通的 P0 垂直切片，从「能玩的占位棋盘」打磨成「雾气里提灯潜行」的成品小游戏。
> 边界：战争迷雾是核心，任何打磨都不得削弱它的三条铁律（见 §2.2）。

---

## 1. 现状诊断

### 1.1 画面

| 现象 | 成因（代码事实） | 后果 |
|---|---|---|
| 屏幕上约 90% 是黑的，只有一个金色大矩形框 | 相机一次装下整张 40×40 地图（`orthoSize = max(20, 20/aspect) + 1.6`），而点亮半径只有 6 格 | 第一眼像「棋盘没画完」，没有场景感 |
| 地形是马赛克色块 | 每格只有 4×4 像素，1 像素格线，纯色填充（`FogHuntView.Cell = 4`） | 放大后能看到像素块，没有材质 |
| 房间与走廊长得一样 | 地图生成只标记 `Blocked`，没有区分房间/走廊 | 走位没有空间记忆点 |
| 迷雾边界是硬的 | 只有 Bilinear 对 4px 块插值，未知区是纯黑 `#0A0D14` | 没有「雾」的质感，只有「黑块」 |
| 单位是几何图形，没有朝向、没有影子 | `FogHuntArt` 只生成圆/三角/菱形/圆环纯色 | 守卫朝向看不出来，无法预判 |
| 墙面平贴在地上 | 墙/地板同一个平面，没有高差表现 | 分不清哪里能走 |

### 1.2 反馈

| 现象 | 成因 | 后果 |
|---|---|---|
| 移动是瞬间跳格 | `_player = target` 后直接改 `transform.position` | 每一步没有重量感，像在拖进度条 |
| 被发现只有左上角 5 个格子变红 | `_detect` 上限 5，UI 是 5 个 23×14 的色块 | 玩家注意不到，失败来得意外 |
| 拾取信标只有一行 Toast | `CollectBeacons` 只调 `_hud.Toast` | 三枚信标中最重要的一次正反馈没有重量 |
| 投石没有落点预览 | 点下即投，`ThrowStone` 直接结算 | 容易点错格，浪费一个回合 |
| 撞墙没有任何回应 | `TryMove` 直接 `return` | 玩家会怀疑「是不是卡了」 |
| 全程静音 | 工程无任何小游戏音效调用 | 潜行游戏没有心跳声，紧张感无从谈起 |

### 1.3 信息层次

| 现象 | 成因 | 后果 |
|---|---|---|
| 没有小地图 | 从未实现 | 「记住走过的路」是迷雾玩法的一半，现在这半没有任何载体 |
| 找不到信标 | 40×40 全黑图，信标位置完全未知 | 玩家只能瞎逛，3 分钟内完不成是常态 |
| 撤离点开局不可见 | `_exit = map.Start` 且与玩家重合，`_exitView` 被玩家盖住 | 集齐信标后不知道怎么回去 |
| 状态卡字号 20~24 | `BuildStatus` 全部 20/24 号 | 1080p 下偏小，读数吃力 |
| 没有开场说明 | 进场景直接开局 | 第一次进来的玩家不知道目标 |

### 1.4 玩法节奏

| 现象 | 成因 | 后果 |
|---|---|---|
| 全程一个强度 | 守卫视野、巡逻、暴露度增长在整局内不变 | 拿到 3 枚信标后回程是走路，没有高潮 |
| 探索率只用于算分 | `ExplorePercent()` 只在结算读取 | 探索本身没有即时回报 |
| 草丛只有「看不见」 | `CanSeePlayer` 里一个 `if` | 没有「擦身而过」的紧张表达 |

**结论**：迷雾的**逻辑**是对的（三态网格、Bresenham 视线、判定与表现分离、每回合先降级再合并），问题全部在**表达层与节奏层**。因此这次打磨不重写玩法内核，只重做「看得见、听得见、有节奏」的部分。

## 2. 设计总纲

### 2.1 一句话

> 把「一张摊平的地图」变成「一盏提灯在雾里挪动」。

### 2.2 不可动摇的四条

| 铁律 | 具体约束 |
|---|---|
| 三态迷雾 | `Unknown / Explored / Visible` 三态不变；离开只降级 `visible`，`explored` 永久保留 |
| 视线遮挡 | 判定仍走 `FogGrid.HasLineOfSight`（Bresenham），墙后不可见 |
| 判定与表现分离 | 一切平滑、光晕、去饱和只作用在遮罩纹理上，逻辑永远读网格 |
| 只看当下 | 敌人/信标/守卫**只在 `Visible` 时显示实体**；`Explored` 只留地形与「记住的位置」 |

### 2.3 三个方向

1. **画面**：地形从 4px 纯色块升级为 16px 程序化材质，迷雾从硬边升级为距离场柔边，相机从全景改为跟随。
2. **反馈**：每一步移动、每一次擦肩、每一枚信标都有位移、光、声三件套。
3. **节奏**：三阶段压力曲线，让「回程」变成整局最紧张的一段。

## 3. 画面

### 3.1 渲染分层

| 层 | 实现 | sortingOrder | 更新频率 |
|---|---|---|---|
| 地形层 | 静态 `Texture2D`（32px/格） | 0 | 进场景一次 |
| 单位层 | 玩家/守卫/信标/出口（含视野锥与阴影） | 9~20 | 每帧（位置） |
| 提灯光晕层 | 暖色径向渐变 `SpriteRenderer` | 30 | 每帧（呼吸） |
| 迷雾遮罩层 | 动态 `Texture2D`（4px/格） | 40 | 每回合一次 |
| HUD | uGUI Canvas（沿用现有 `FogHuntHud`） | 100 | 事件驱动 |

遮罩画在所有世界物体之上、HUD 之下。这样「雾盖住敌人」是天然成立的；单位显隐仍然单独控制（`Visible` 判定），遮罩只负责画面。

### 3.2 地形贴图

- 尺寸：40×40 格 × 32px = 1280×1280，`RGBA32`，约 6.5MB。
- 生成一次，之后不再重算；`FilterMode.Bilinear`，在 1080p 下每格约 71 屏幕像素，放大 2.2 倍不糊。

| 区域 | 画法 |
|---|---|
| 房间地面 | 石板：12×12 内部 + 1px 灰缝，每块独立亮度抖动 ±6% |
| 走廊地面 | 泥土：底色 + 高频噪点，无砖缝 |
| 墙 | 2.5D 石块：底色 `#343A46`，顶部 3px 亮边 `#4E5766`，底部 3px 暗边 `#23272F`，噪点斑驳 |
| 草丛 | 地面色 + 4~6 道草叶短线（深绿→浅绿），格内随机分布 |
| 墙脚 AO | 与墙相邻的地面格整体乘 0.86，形成接缝阴影 |

地图生成器需要额外输出 `IsRoom[x,y]`（房间内/走廊），只用于美术选择，不参与判定。

### 3.3 迷雾遮罩

- 尺寸：40×40 格 × 4px = 160×160，`RGBA32`，约 100KB；`FilterMode.Bilinear`。
- 每回合重算一次，算法分三步：

```
① 距离场：从所有 Visible 格做 BFS，得到每格到「可见区」的距离 d
② 逐格写 alpha：
     Visible   → alpha = smoothstep(0, 1.6, d) * 0.10        // 灯心几乎透明
     Explored  → alpha = 0.52 + smoothstep(0, 1.6, d) * 0.10  // 记忆区压暗、偏蓝
     Unknown   → alpha = 1.0                                  // 纯黑
   颜色统一取 #070A10，Explored 额外叠一点蓝 (#0B1424)
③ 3×3 均值模糊一遍，消除 BFS 的方块感
```

- 遮罩纹理用 `SetPixels32` 整张上传，25 600 像素，单回合耗时 < 2ms。
- 未知区颜色与相机背景色取同一个值 `#05070B`，这样地图外与未探索区无缝。

### 3.4 提灯光晕

- 一张 128×128 的径向渐变贴图（程序化生成），暖色 `#FFC46A`，`alpha` 峰值 0.14。
- 跟随玩家，缩放 6.5 格；呼吸周期 2.4s，幅度 ±6%。
- 绘制在迷雾遮罩之下，光晕超出可见区的部分会被雾自然吞掉。

### 3.5 相机

| 项 | 值 |
|---|---|
| 模式 | 跟随玩家（`SmoothDamp`，0.12s） |
| 视野 | `orthographicSize = 7.6`（竖屏约 15.2 格，16:9 横向约 27 格） |
| 背景色 | `#05070B`，与未知雾一致 |
| 地图边框 | 删除现有金色大画框（`FogHuntView.BuildFrame`） |
| 投石模式 | 相机轻微拉远 8%，0.2s 过渡 |

跟随相机不会削弱迷雾：玩家看得见的范围仍由 `PlayerSight = 6` 决定，相机只是把「有意义的那 15 格」放到屏幕上。

### 3.6 单位

| 单位 | 表现 |
|---|---|
| 玩家 | 青色圆身 + 朝向小三角 + 脚下椭圆软阴影（0.32×0.16，alpha 0.35） |
| 守卫 | 红色三角（指向 `Facing`）+ 阴影；**仅在 `Visible` 时**叠加 ±60° 视野锥（半透明红，边缘 1px 亮线） |
| 守卫被激怒 | 视野锥由 `0.16` 提到 `0.30` 不透明度，守卫转向玩家 |
| 信标 | 金色菱形 + 竖直光柱（渐变贴图，加法）+ 2.0s 呼吸；拾取后原地留 0.5s 余晖再消失 |
| 出口 | 双环 + 淡绿呼吸；集齐 3 枚后变金色、脉动加快一倍，并在小地图上闪动 |

### 3.7 性能预算

| 项 | 预算 |
|---|---|
| 地形生成 | 进场景一次，< 150ms |
| 遮罩重算 | 每回合 < 3ms（25 600 像素 + BFS） |
| 小地图重算 | 每回合 < 1ms（160×160） |
| 总内存新增 | < 9MB（地形 6.5MB + 遮罩 0.1MB + 小地图 0.1MB + 其余贴图） |

回合制没有逐帧负担，以上预算留了充足余量。

## 4. 手感与反馈

### 4.1 移动

- 位移用 0.12s 缓出插值（`transform.position` 从旧格到新格），期间不接受下一次输入。
- 落地瞬间：脚下扩一圈 0.2 格→1.0 格的淡环，alpha 0.4→0，0.25s。
- 撞墙：目标格不可走时，玩家向该方向抖 0.06 格再弹回（0.12s），同时播一次闷响。
- 撞到守卫占据格：同上，但抖得更明显并播放金属摩擦声。

### 4.2 守卫

- 视野锥只在守卫 `Visible` 时绘制；锥体用半透明扇形贴图（程序化生成 64×64 扇形），随 `Facing` 旋转。
- 发现玩家后：锥体颜色由 `#FF5C4D@0.18` 提到 `#FF3B2E@0.30`，并让守卫朝玩家转向。
- 守卫移动同样走 0.12s 插值，与玩家节奏一致。

### 4.3 信标与撤离

- 拾取：金色尘环由 0.7 格扩到 2.4 格（0.48s）+ 10 颗小金点四散（0.46s）+ 全屏淡金闪（0.24s，alpha 0.02）。
- 集齐 3 枚：出口高亮 + 一声长鸣 + 所有守卫进入收拢（见 §6）。

### 4.4 暴露度

- 内部保持 0~5 的浮点（现逻辑不变），UI 显示为百分比进度条 + 三档文案：

| 区间 | 颜色 | 文案 |
|---|---|---|
| 0 ~ 0.2 | `#6FD3FF` | 潜行中 |
| 0.2 ~ 0.6 | `#FFB347` | 被怀疑 |
| 0.6 ~ 1.0 | `#FF4D3D` | 即将暴露 |

- 暴露度 ≥ 0.6 时，屏幕四边叠加呼吸红晕（vignette 贴图，alpha 0.06~0.14，周期与心跳同步）。
- 心跳声随暴露度提高而加快：0.9s → 0.5s 间隔，满值前 0.35s。

### 4.5 投石

- 进入投石模式：脚下显示 6 格射程圈（青色描边，画在雾下，远处自然变暗），光标所在格显示落点框，相机拉远 8%。
- 投石本身不消耗额外资源，投出后立即结算一个回合。

## 5. 信息层次

### 5.1 HUD 布局

```
┌──────────────────────────────────────────────┬─────────────┐
│ 回合 12/120   信标 1/3                        │  小地图      │
│ ████████████░░░░░░  被怀疑                     │  200×200    │
└──────────────────────────────────────────────┴─────────────┘

                                    ┌───────────────┐
                                    │  蹲伏 / 投石   │
                                    │  设置          │
                                    └───────────────┘
  ┌───────────┐
  │  ↑        │         WASD/方向键 移动 · Q 蹲伏 · E 投石 · Esc 设置
  │ ← ↓ →     │
  └───────────┘
```

- 左上状态条：一行「回合 / 信标」，下面一条暴露度进度条 + 状态文案；字号 26。
- 右上小地图：200×200，圆角 12，1px 金色描边，右下角标 N。
- 左下方向键、右下功能键：沿用现有按钮，字号提到 26/28，圆角 14。
- 底部提示：常驻一行，字号 20，颜色 `#8FA0B3`。

### 5.2 小地图规则（必须与铁律一致）

| 元素 | 显示规则 |
|---|---|
| 地形 | 只画 `Explored`（含当前 `Visible`），未探索纯黑 |
| 玩家 | 青色圆点 + 朝向短线 |
| 出口 | 常显（这是已知目标），金色描边 |
| 信标 | 只在被看到过之后标出「记住的位置」；被拾取后变成空心灰点 |
| 守卫 | **永不显示**（记住路 ≠ 知道敌人在哪） |

### 5.3 目标指引

- 任一未拾取信标距玩家 ≤ 8 格时，状态条旁边出现一行「信标 · 西北 7 格」，方向按八向。
- 该提示只给方向与距离，不给坐标，不给小地图标记 —— 保留「不知道路上有什么」的悬念。

### 5.4 开场卡

进入场景后 0.8s 淡入：

```
        迷雾信标
   找回 3 枚信标，回到入口
   你只能看见灯照到的地方

      [ 任意键开始 ]
```

3 秒后自动开始，按键可立即开始；开始后 0.4s 淡出。

### 5.5 结算页

| 区块 | 内容 |
|---|---|
| 评级印章 | 直径 140 的圆环 + 大号 S/A/B/C，成功金色、失败灰红 |
| 数据 | 用时回合 / 信标 / 暴露度峰值 |
| 分数 | 评级分×100 + 剩余回合 + 探索率，逐项列出 |
| 排名 | 新纪录 / 当前排名 / 历史最高 |
| 操作 | 再来一局（扣次数）/ 返回主页 |

## 6. 玩法节奏

| 阶段 | 触发 | 规则变化 | 表达 |
|---|---|---|---|
| ① 潜行 | 开局 | 现有规则 | 守卫巡逻，视野 5 |
| ② 戒备 | 拾取第 1 枚信标 | 守卫视野 5 → 6；暴露度增长 ×1.25 | Toast「守卫察觉到了什么」+ 一声闷雷 + 小地图闪红边 |
| ③ 撤离 | 拾取第 3 枚信标 | 所有守卫以入口格为噪音点收拢（复用 `Guard.Noise`）；暴露度增长 ×1.5；出口高亮 | 长鸣 + 出口脉动 + 提示「带着信标回去」 |

- 阶段只升不降，符合「先潜行、后追逐」的曲线。
- 守卫收拢复用现有 `Noise` 机制（`GuardsAct` 已有该分支），不新增 AI 代码。
- 三个阶段在结算页作为「本局经过」展示，增强回看欲望。

## 7. 音频

本轮不接入音频，所有打磨都通过画面、位移与光效完成反馈。声音的接入位置集中在三个方法（移动结算、拾取、结算），后续补音效时只在这三处调用 `MieMieFrameWork.AudioManager.PlayOneShot`，不改动任何玩法与渲染代码。

## 9. E2E 验收

### 9.1 功能（数据断言，优先）

| # | 断言 |
|---|---|
| A1 | 从 LOGIN 登录 → 活动面板 → 迷雾信标 → 开始探索 → `scene.name == "fog_hunt"` |
| A2 | 连续 `UiMove` 后 `turns` 严格递增，`player` 坐标按方向变化，撞墙时坐标不变 |
| A3 | `FogGrid` 三态分布：`Unknown + Explored + Visible == 1600`，且 `Visible` 只出现在玩家视野半径内 |
| A4 | 走开再回来：曾可见的格 `Explored`，不可见时不回退成 `Unknown` |
| A5 | 拾取 3 枚后 `collected == 3`，出口格出现高亮；踏上出口 → `Over == true` 且评级非空 |
| A6 | 暴露度满 → `Over == true` 且结果为失败 |
| A7 | 阶段切换：拾第 1 枚后守卫视野为 6；拾第 3 枚后每个守卫 `Noise == 出口` |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 相机跟随让「记住的路」失去意义 | 小地图承担记忆载体，且严格只显示已探索格 |
| 遮罩 4px/格在大屏上仍能看出格 | 距离场 + 3×3 模糊 + Bilinear；若仍明显，提到 8px/格（成本 ×4，仍在预算内） |
| 16px/格地形贴图在 4K 下偏糊 | `FilterMode.Point` 保持像素质感；几何图形不用位图 |
| `UICameraService.SweepAll()` 每秒改写 Canvas 模式 | HUD 沿用现有 `BuildCanvas`（ScreenSpaceOverlay + 自带 GraphicRaycaster），不与之抢模式 |
| 音频资源缺失或 `AudioManager` 未初始化 | `FogHuntAudio` 全部调用判空 + try/catch，缺资源只少声音不影响玩法 |
| 阶段 ③ 守卫收拢后无解 | 收拢速度与巡逻一致（每回合 1 格），玩家距离入口通常更近；连续 3 局实测通过率 ≥ 40% 才保留该规则 |
| 活动页文案改动不生效 | 文案在 `activity_main.lua.txt`，必须重新构建并发布活动包（`UseHostPlayMode=true`） |
| 打磨过程中破坏迷雾判定 | `FogGrid` 不在改动清单内；每次提交前跑 A3/A4 断言 |
