# 登录界面跨场景残留（BUG 修复记录）

> 目标工程：`D:\tuanjieproject\frined\RedDotSystem-main`　日期：2026-10-21
> 现象：登录成功进入主城/挑战场景后，登录界面（LoginPanel）仍然叠在新场景画面上。

## 1. 根因

1. `LoginSceneBootstrap.EnsurePanelAsync` 用 `ResourceManager.Instance.InstantiateAsync` 从 ui 包实例化 `Assets/Game/UI/Login/LoginPanel.prefab`。
2. `ResourceManager.InternalInstantiate` → `InstancePool.InitInst`（`InstancePool.cs:117`）把实例 `SetParent` 到 `GameObjectPool` 根节点；
   而该根节点在构造函数里做了 `DontDestroyOnLoad`（`InstancePool.cs:18`）。
3. 因此登录界面实际挂在 **DDOL** 层级下，`SceneLoader` 的 `LoadSceneMode.Single` 不会销毁它 → 进入 zhuye / tiaozhan 后继续显示。
4. 框架自己的 UI（`UIManager.Open`）会在实例化后把界面重新挂到对应层的 Canvas 下，所以只有登录界面这种"裸实例化"的对象会泄漏。

## 2. 修复方案

**把登录界面的生命周期绑到 LOGIN 场景**：`LoginSceneBootstrap.Awake` 建，`OnDestroy`（离开场景时）毁；
下次进入 LOGIN 场景（退出登录 / 被顶号踢回）由 Awake 重新实例化 —— 即"用完即毁，用时再建"。

- `LoginSceneBootstrap` 新增 `OnDestroy → DestroyPanel()`：
  - 单场景切走时，Unity 卸载 LOGIN 场景 → Bootstrap 的 `OnDestroy` 触发 → 连带销毁 DDOL 池根下的登录界面；
  - 卸载发生在加载页还盖着的时候，所以新场景第一帧就不会露登录界面（不需要额外隐藏）；
  - 若切场景失败（场景未进 Build Settings），LOGIN 场景不卸载 → 界面保留，玩家还能继续操作。
- 销毁走 `ResourceManager.Recycle(obj, forceDestroy: true)`，保证 ui 包实例计数与 `_objectInstanceIdKeyDic` 同步扣减；
  场景里手摆的调试界面（不归 ResourceManager 管）直接 `Destroy`。为此给 `ResourceManager` 增加只读判断 `IsManagedInstance(GameObject)`。
- `LoginSceneController` 不改：登录流程只管切场景，界面归属交给场景本身。

## 3. 影响面

| 文件 | 改动 |
|---|---|
| `Assets/Game/Scripts/UI/Framework/Common/ResourceManager.cs` | 新增 `IsManagedInstance(GameObject)` |
| `Assets/Game/Scripts/Network/LoginSceneBootstrap.cs` | 新增 `OnDestroy → DestroyPanel()`，界面随场景销毁 |

不改 `InstancePool` / `SceneLoader` / `UIManager`：DDOL 池是框架既有设计（复用实例、避免反复加载），问题只在于"用完没还"。

## 4. 验收

- [ ] 登录成功 → 主城：看不到任何登录界面残留。
- [ ] 主城 → 挑战（tiaozhan）：无登录界面残留。
- [ ] 退出登录 / 被顶号踢回 LOGIN 场景：登录界面正常重新出现，可再次登录。
- [ ] 重复"登录 → 退出 → 登录"三次：不出现两份界面，控制台无 `此模块不回收不是从这个模块实例化出去的对象` 报错。
- [ ] 场景切换失败（如场景未进 Build Settings）：登录界面恢复显示，不卡死。
