### 1.5 KCC（Assets/Plugins/KinematicCharacterController-main）

- asmdef：`Gawidev.KCC`（rootNamespace `KinematicCharacterController`，`autoReferenced: true`）。

- 示例：`Samples/SimplePlayerController.cs`（相机相对 WASD + 重力 + 跳跃 + 贴地力 + 转身平滑，实现了 `ICharacterController` 全接口）。
- 关键限制（来自示例注释）：**角色根节点 Scale 必须为 (1,1,1)**；不要挂 Rigidbody；`Awake` 里必须 `motor.CharacterController = this`。

## 2. 方案对比与选择

### 2.1 移动控制器

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **KCC（本项目已有）** | 台阶/斜坡/贴地/边缘处理完善；与挑战场景手感一致 | 需要自己写控制器；FixedUpdate 模拟 | ✅ 采用（用户指定） |
| CharacterController（旧 demo） | 现成、改动最小 | 台阶/斜坡会卡；胶囊贴地粗糙 | 备选 |
| 自研 sweep | 无依赖 | 重复造轮子 | 不采用 |

### 2.2 相机

| 方案 | 结论 |
|---|---|
| 复用现有 `CM_FreeLook`（三环绕 FreeLook） | 手感偏“原神探索”，但与挑战场景不同 → 不采用 |
| **挑战同款 VirtualCamera + FramingTransposer + POV** | ✅ 采用（参数逐项一致） |
| 固定机位 | 不采用 |

### 2.3 角色动画

| 方案 | 结论 |
|---|---|
| **Animator + AnimatorController（Idle/RunFwd，Speed 混合）** | ✅ 采用：与现有 `l.controller` 一致、零额外依赖 |
| Animancer（战斗角色用） | 不采用：本场景只有 2 个状态，用不上 |
| Timeline | 不采用 |

### 2.4 设置面板

| 方案 | 结论 |
|---|---|
| 场景内简易 SettingsPanel（旧 demo 时钟/音乐） | 功能太少 |
| **框架 `SettingsView` + 暂停 + 「返回主页」** | ✅ 采用（用户指定） |
| 两者合并 | 不做 |

### 2.5 环境碰撞

| 方案 | 结论 |
|---|---|
| FBX 导入时 Generate Colliders（36 个网格全加 MeshCollider） | 太重，且 SkinnedMesh 碰撞体是静态的 |
| **地板 1 个 BoxCollider + 四周墙体 4 个 BoxCollider** | ✅ 采用：本场景只走不跳，够用、可控 |
| 家具逐个加碰撞 | 可选（沙发/吧台作为装饰，默认不加） |

## 3. 方案设计

### 3.1 入口与加载（主页 → 对话场景）

```

  → HomeView.EnterDialogueScene()
      · 已在 duihua 场景则直接 return
      · await UIManager.Close(HomeView)     // HomeView 常驻，不关会盖在新场景上（挑战入口已有同款处理）
```

- 加载过程中 `SceneLoader.IsLoading` 防重入；重复点击只打警告。

删除：场景里的巨型 `Plane`（scale 1000×1×100000，会与大厅地板打架）。

### 3.3 环境与碰撞

- 站位地面：大厅地板网格顶面（`000_材質1` 包围盒推算 y≈1.05，实施时用射线/顶点再精确验证）。
- 碰撞：`Environment/Collision` 下
  - `Floor`：BoxCollider，覆盖大厅可行走区域（约 16 × 50），顶面 = 地板高度；
  - `Wall_N/S/E/W`：4 个 BoxCollider 防止走出大厅；
  - Layer 设为 `environment`（KCC `StableGroundLayers` 只认地面层）。
- 灯光：保留 FBX 自带 Point Light（预览亮度自然）；若角色偏暗，补一盏低强度 Directional Light 作角色补光。
- 保留现有 `PostFX_Volume`。

### 3.4 545（玩家）与 KCC

**根节点组件**（顺序重要）：

1. `CapsuleCollider`：center = (0, 0.8, 0)，radius ≈ 0.3，height ≈ 1.6（按 545 身高 1.57 微调）。
2. `KinematicCharacterMotor`：
   - `Capsule` 自动取同物体 CapsuleCollider；
   - `MaxStableSlopeAngle` 60、`StepHandling` Standard、`MaxStepHeight` 0.35；
   - `StableGroundLayers` = environment 层。
3. `DialoguePlayerController`（新脚本，`ICharacterController`）：
   - `Awake`：`motor.CharacterController = this`；
   - `Update` 采样输入（`Input.GetAxisRaw`，`activeInputHandler=Both` 已确认可用）+ `TestMoveInput` 测试钩子；
   - `UpdateVelocity`：贴地切向速度 + 贴地力；空中重力；
   - `UpdateRotation`：朝移动方向平滑转（`1-exp(-k·dt)`）；
   - 输出 `Animator.SetFloat("Speed", planarSpeed/runSpeed)`；
   - `InputLocked`（对话/暂停时置 true）。
4. `Animator`：`Avatar=545Avatar`，`Controller=l.controller`，`Apply Root Motion=false`。

**模型子物体**：`545.fbx` 实例，位置 (0,0,0)；若模型正面与角色根 +Z 不一致，给模型子物体加 180° Y 旋转（实施时用截图确认朝向）。

**层级 / Layer**：角色 Layer 设为 `player`（3），供后续交互与相机遮挡判断使用。

**初始站位**（大厅中央偏休息区，金额可调）：
- 545：`(0, floorY, -5)`，朝向 +Z；
- 流萤：`(0, floorY, -1)`，朝向 -Z（与 545 相对）；
- 间距 4m；交互半径 3m → 向前走约 1m 即触发。

**移动参数**：`MoveSpeed=3.2`、`GroundAcceleration=45`、`StickToGroundForce=18`、`Gravity=22`；不跳跃（本场景无跳跃需求，减少误触）。

### 3.5 流萤（NPC）

1. **Avatar**：`ModelImporter.animationType = Humanoid`（Rig → Human），让 Unity 依据 798 根 MMD 骨自动生成 Avatar；实施后检查 `avatar.isValid`。
   - 若自动映射不完整：手动补齐关键骨（Hips/Spine/Chest/Neck/Head/上下臂/腿/脚），或退回“静态站姿 + 轻微程序化起伏”。
2. **Animator**：新建 `LiuyingIdle.controller`（Base Layer：`Idle` 循环，`Idle2/Idle3` 可加随机待机），`Apply Root Motion=false`。
3. **朝向**：对话开始时由 `GenshinDialogDirector` 与玩家双向平滑转向（沿用现有 0.3s SmoothStep 协程）。
4. **交互**：`DialogueInteractionZone` 挂在流萤根节点，`player` 指向 545；3m 内显示 `[F] 交谈 · 流萤`。

## 9. 实施记录与实测结论（2026-10-25）

### 9.1 实际落地与文档设计的差异

| 项 | 设计 | 实际 | 原因 |
|---|---|---|---|
| KCC 胶囊尺寸 | 直接改 `CapsuleCollider` | **改 Motor 的私有序列化字段 `CapsuleRadius/Height/YOffset`** | `KinematicCharacterMotor.Awake` 会用自身字段重写胶囊；只改 Collider 会在运行期被打回 0.5/2.0 |
| 第三人称相机输入 | 复用挑战场景相机对象 | 新建 vcam + FramingTransposer + POV（**不挂 `CinemachineInputProvider`**） | 挑战场景/预制体上的 `XYAxis/ZAxis` 都是空的，Provider 会返回 0 把 POV 卡死；不挂 Provider 时 POV 走 legacy `Mouse X/Y`（项目 Active Input Handling=Both） |
| 滚轮缩放 | 复用 `Camera_ZoomController` | 新写 `DialogueCameraZoom` 读 `Input.mouseScrollDelta` | 同上：`Camera_ZoomController.GetAxisValue(2)` 取的是空 ZAxis，恒 0 |
| 对话机位 | 固定偏移 0.55/0.45 | **按两人间距自适应后拉**（`comfortableDistance=1.6`） | 玩家能贴到 NPC 身上（0.8~1m），固定偏移会把镜头顶进说话者头发里，画面全黑只剩剪影 |
| 环境主光 | 保留 FBX 自带 Point Light | 该 FBX 实例里没有 Light；场景实际是 `Directional Light`（yaw330，朝 +Z 打） | 玩家正面朝 +Z 正好背光，反打开场是剪影 → 新增 **`CharacterFillLight`**（Directional 0.75、无阴影、yaw155） |
| 场景菜单 | 沿用 `GenshinMenuController` | 新写 `DialogueSceneMenu`（Esc + HUD 设置按钮），旧组件删除 | 旧脚本绑定的是已删除的背包/时钟面板 |
| 交互提示文案 | 未写 | `交谈 · 流萤` | 旧 demo 是“交谈 · 未名” |

### 9.4 踩坑

1. **KCC 胶囊由 Motor 接管**：`CapsuleRadius/CapsuleHeight/CapsuleYOffset` 是 private `[SerializeField]`，`Awake` 里 `SetCapsuleDimensions` 会覆盖 `CapsuleCollider`；用 `SerializedObject` 改 Motor 字段才持久。
2. **`CinemachineInputProvider` 空轴 = POV 死**：CM 2.10 里 Provider 存在但 `XYAxis/ZAxis` 为空时 `GetAxisValue` 恒返回 0 并覆盖 legacy 轴；挑战场景/预制体当前就是这种“没有鼠标视角”的状态。
3. **点光/方向光的方向决定对话镜头曝光**：hall 的 Directional Light yaw330 朝 +Z，玩家正面背光；反打镜头整片剪影 → 需要一盏无阴影补光，不能靠调主光。
4. **对话机位要按间距自适应**：固定“肩后 0.55m”在两人贴近时等于把镜头塞进头发，症状是“整屏发黑只剩剪影”，很容易被误判成黑屏/材质 bug。
5. **本机内存压力**：paged memory 到 94%（46GB/49GB）时，`UIManager` 首次在重场景里初始化会刷 “The system is running out of memory” 并卡住协程；正常流程（zhuye 先初始化 UI，再经 CTA 进 duihua）无此问题。复测时不要再用“直接 Play duihua 并首次开 UI”这条路径做断言。
6. `GameObject.Find("545")` 会命中模型子物体（与根同名）→ 子物体已重命名为 `545_Model` / `流萤_Model`。

## 10. 修正记录（2026-10-25 用户反馈：悬空 + 太暗）

### 10.1 悬空：地板高度取错网格

- 初版用 `000_材質1` 的包围盒顶面 **1.044** 当地板高度，但那是大厅里的高台/结构，不是行走面。
- 用 `SkinnedMeshRenderer.BakeMesh()` 逐网格生成临时 MeshCollider、在角色脚下（x=0，z=-6/-2/-4）垂直射线实测：真正的地板是 **`011_材質12`，顶面 y = 0.192**（三条射线全部命中同一高度）。
- 修正：地板 BoxCollider 顶面改为 0.192、四周墙随之下降；545 根节点 y=0.202（脚底 0.194）、流萤根节点 y=0.222（模型脚底相对根 -0.028，抬 1cm 后脚底 0.194），两人都贴地。
- 新截图 `screenshots/tuned_frame2.png` 可见靴子踩在浅灰地面上。

### 10.3 鼠标不能转视角（2026-10-25 用户反馈）

- 根因：`CinemachinePOV` 的 `MaxSpeed` 沿用了挑战场景的值（水平 **0.22**、垂直 **0.05**）。Cinemachine `AxisState` 在 `SpeedMode.MaxSpeed` 下把 `m_MaxSpeed` 当**度/秒**用，`targetSpeed = input * m_MaxSpeed` —— 0.22°/s 等于鼠标完全转不动（挑战场景那台相机本身也因为 `CinemachineInputProvider` 的 XY/Z 轴为空而一直是 “没有鼠标视角”的状态）。
- 同时游玩态是**不锁鼠标**（为了能点 HUD 设置按钮），指针顶到 Game View 边缘后 `Mouse X` 增量会归零，也会表现为“转不动”。
- 修正：
  - POV 水平 `MaxSpeed = 260`、垂直 `170`，Accel/Decel 0.05，保留 Y 反转与 -30~70 范围、水平 Wrap；
  - `GenshinDialogDirector.lockCursorInGameplay = true` —— 游玩时锁定并隐藏指针（对话/暂停时自动释放，见 `UpdateCursorState`）；
  - 锁定后 HUD 设置按钮在游玩态点不到，改用 **Esc** 打开设置（暂停后指针自动释放，按钮也可点）。
- 实测（新会话、不移动鼠标）：`cursor=Locked/visible=False`，静止 0.5s `ΔH=0.0 / ΔV=0.0` 不漂移；用 `CinemachineCore.GetInputAxis` 注入 `Mouse X=1` 0.4s → **yaw +94.1°**（约 235°/s），链路正常。
- 手感微调入口：`CM_ThirdPerson` → `CinemachinePOV` 的 H/V `MaxSpeed`（数值越大越灵敏）。

### 10.4 可以穿过场景模型（2026-10-25 用户反馈）

- 根因：大厅模型是 `SkinnedMeshRenderer`（36 个网格），FBX 导入时没有生成碰撞体，SkinnedMeshRenderer 也不会自动带 Collider；初版只手动加了「地板 + 四面边界墙」，所以沙发、吧台、绿植、门框全部可以穿过去。
- 修正：给 `未命名` 下 **36 个网格各挂一个 MeshCollider**（`convex=false`、layer=environment），直接使用 `SkinnedMeshRenderer.sharedMesh`。
- **坑：不要用 `BakeMesh` 的结果直接挂回 SMR 变换**。本工程（Tuanjie）的 `BakeMesh` 返回的顶点已经包含 transform 的 100 倍缩放，再套用 SMR 的 lossyScale 会得到 100 倍大的碰撞体（表现为“整个大厅都是巨大碰撞体”）。要么把顶点除以 `lossyScale` 再挂，要么直接用 `sharedMesh`——实测两者碰撞面完全一致（地板 0.003、沙发 0.897/1.293），`sharedMesh` 零额外资产（BakeMesh 方案会产生 ~10MB 网格资产）。
- 顺带修正地板高度：用正确的碰撞网格实测，**可视地板顶面是 `0.003`**（之前 0.192 是“BakeMesh 被放大 100 倍”那次测量得到的错误值，角色其实还悬空约 0.19m）。现在 545 根 y=0.011、流萤根 y=0.031，脚底 0.003 贴地；原地板 BoxCollider 降到 -0.017 只当安全网。
- 验证：射线扫描能命中家具（沙发 0.897/1.293）；Play 里长按左右各 5~8 秒，角色在 **x ≈ ±4.67** 处被沙发/花坛挡住（不是走到墙边 8.2），`grounded` 全程 true，没有穿模/掉出场景。

### 10.5 角色自己走路（2026-10-25 用户反馈）

- 现象：完全不给输入，角色以稳定 **0.36 m/s** 沿 -Z 缓慢滑行（静置 4 秒位移 1.44m），但 `Horizontal/Vertical` 与 `moveInput` 都是 0、`Animator Speed` 也是 0。
- 根因：控制器在着地分支每帧给速度加“贴地力” `n * (-StickToGroundForce * deltaTime)` = `18 × 0.02 = 0.36`，**是纯竖直分量**；而 KCC 在着地后会把 `BaseVelocity` 投影到水平面并**保留模长**（`GetDirectionTangentToSurface(...) * BaseVelocity.magnitude`）。静止时没有水平方向可投影，这个 0.36 的竖直速度就被“旋转”成了水平速度，于是每帧稳定自走。
- 修正：贴地分量只在**有移动意图**时施加（`moveInput.sqrMagnitude > 0.0001f`），静止时不再注入竖直速度。
- 实测：静置 3 秒位移 **0.0000**、`baseVel=0`；移动 1.5 秒前进 3.39m、`Speed=1.0`；松手后 `baseVel=0` 且再静置 1.5 秒位移 0。
- 同类经验：KCC 官方最小示例的贴地力写法在“静止 + 平地”下会产生自滑，使用时要加移动门限或换成只影响着地判定的写法。
