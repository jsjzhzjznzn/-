# 场景加载统一入口（SceneLoader）方案

> 编写日期：2026-10-23
> 定位：施工单。把 8 处同步 SceneManager.LoadScene 收敛成一条异步入口，**不改变任何场景的加载模式与业务顺序**。

---

| 项 | 内容 |

## 2. 设计

### 2.1 入口 API

```csharp
// Framework/F_Scene/SceneLoader.cs（全局命名空间，调用方零 using）
public static class SceneLoader
{
    public static bool IsLoading { get; }

    // 异步切换场景；加载中重复调用直接返回（只打一条警告），不会叠加两次加载
    public static UniTask LoadAsync(string sceneName, Action onLoaded = null,
                                    LoadSceneMode mode = LoadSceneMode.Single);
}
```

**为什么用 onLoaded 回调而不是只让调用方 await**：KickoutWatcher 的提示必须在新场景加载完之后弹出（ActivityLoadingTip 不是 DDOL，加载中被销毁就看不见），其余调用点 await 或 .Forget() 都支持。

### 2.2 加载流程

```text
显示 LoadingScreen（全屏遮罩，独立 Canvas + DDOL）
  → LoadSceneAsync(name, mode)，allowSceneActivation = false
  → 循环 progress（0~0.9 映射到 0~1）刷新进度条
  → 进度到 1 后至少停留 0.35s（避免一闪而过）
  → allowSceneActivation = true，等 isDone
  → 淡出并销毁 LoadingScreen
  → 回调 onLoaded
```

要点：allowSceneActivation = false 是拿到真实进度的前提；否则 progress 会卡在 0.9，无法展示中间态。

### 2.3 加载界面（LoadingScreen）

- **纯程序化构建**：Canvas(Overlay, sortingOrder 32760) + CanvasScaler(1920x1080) + GraphicRaycaster，黑底 + 提示文字 + 进度条。不依赖 UIManager / UIConfig / YooAsset，任何场景（包括 UI 框架未就绪的 LOGIN）都能用。
- 沿用 DungeonHud 的先例：Awake 自建 Canvas、无美术依赖。
- DontDestroyOnLoad，加载结束时自毁。
- 遮罩全屏且带 GraphicRaycaster，天然挡住连点。

### 2.4 NGO 场景为什么不纳入

RoomState.cs:588 的 _nm.SceneManager.LoadScene 由 NGO 的 NetworkSceneManager 驱动：服务端决定何时切、客户端跟随，还要同步 NetworkObject。换成 Unity 原生 SceneManager 会导致多端场景不同步，因此保持原样并加注释说明。

## 4. 边界与失败处理

| 场景 | 处理 |
|---|---|
| 场景名不在 Build Settings | LoadSceneAsync 返回 null → 报错 + 收起加载界面 + 不回调 |
| 加载中重复点击 | IsLoading 拦截，打一条警告并返回 |
| 加载中对象被销毁 | LoadingScreen 自带 DDOL，不受场景卸载影响 |
| onLoaded 抛异常 | try/catch 包住，只记录日志，不影响加载流程 |
| Additive 模式 | API 支持，当前无调用者，行为与 Single 一致 |

## 7. 明确不做

| 不做 | 原因 |
|---|---|
| 不改 RoomState 的 NGO 场景切换 | 会让多端场景不同步 |
| 不动 ResourceManager.LoadSceneAsync | 无调用者，改动无收益；登记为死代码待清理 |
| 不引入 YooAsset 场景加载 | 当前场景都在 Build Settings，直连 Unity 即可；混用会让哪些场景走热更变成两套真相 |
| 不做加载界面美术 | 纯色 + 文字 + 进度条够用，且零依赖 |

> **MCP 的 `refresh_unity` 不会导入新增文件。** 新建 `.cs` 后必须再执行 `AssetDatabase.Refresh()`，否则 Unity 根本不编译它，而 `read_console` 仍然返回 0 错误——这个「0 错误」是假象。
>
> 验证依据：新增 `F_Scene/SceneLoader.cs` 后第一次 refresh，`Assembly-CSharp.csproj` 里 0 条 `F_Scene` 记录、磁盘上也没有 `.meta`；执行 `AssetDatabase.Refresh()` 后才出现 2 条 csproj 记录和 `.meta`。
