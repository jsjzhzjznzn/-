# 对战大厅 / 加入房间 / 选人界面 美化方案（含创建房间修复）

> 目标：修复「创建房间」点击无效，并把对战大厅、加入房间、选人房间统一成一套可维护的
> 「深色战术 HUD + 金色描边」视觉；不改联机逻辑、不改控件绑定名。

---

## 0. 结论先行

### 0.1 创建房间失败（已定位并修复）

报错：

```
The referenced script on this Behaviour (Game Object 'BattleNetworking') is missing!
BattleNetworkLauncher.EnsureInstanceAsync -> Instantiate(Resources/Battle/BattleNetworking)
```

排查结果：

| 检查项 | 结果 |
| --- | --- |
| `Assets/Game/Resources/Battle/BattleNetworking.prefab` 是否存在 | 是 |
| 根节点组件 | Transform / NetworkManager / **缺失脚本** / RoomState |
| 缺失位置对应的 YAML 组件 | `m_Script guid: 6960e84d...` = 嵌入式 NGO 包里的 `UnityTransport.cs` |
| `MonoScript.GetClass()` | **null**（脚本资产存在，但编辑器没有把它关联到已编译类型） |
| `typeof(UnityTransport)` | 能找到，位于 `Library/ScriptAssemblies/Unity.Netcode.Runtime.dll` |
| 强制 `AssetDatabase.ImportAsset(UnityTransport.cs, ForceUpdate)` | `GetClass()` 恢复，预制体缺失组件数 **1 → 0** |

结论：**预制体没有坏，是嵌入包脚本的 MonoScript 导入状态失效**（Tuanjie 重导入/包更新后常见）。
已执行强制重导入修复。为防止以后复发，会加一个编辑器菜单：

`Tools/Battle/修复联机预制体缺失脚本`
→ 重新导入 `UnityTransport.cs` + 检查 `BattleNetworking.prefab` 缺失组件数 + 输出结果。

> 本次美化不会重建 `BattleNetworking.prefab`（现有 `P3 一键构建` 会重建它，正是最容易再次踩坑的入口）。

### 0.2 视觉方向

「深色战术 HUD + 金色描边」：保留对战界面的暗色底，用主页已有的金色/米白作为强调，
与 HomeView 的金色元素呼应；绿色只用于主操作，红色只用于退出/关闭，蓝色用于次要信息。

## 4. 实现方式

### 4.1 修改现有构建器，而不是另写一套

`Assets/Game/Scripts/Battle/Lobby/Editor/BattleLobbyPrefabBuilder.cs`

- 重写 `BuildLobbyView()` / `BuildJoinRoomView()` / `BuildRoomView()` 的视觉布局。
- 新增通用帮助函数：
  - `AddBorder(Image parent, Color color, float inset)`
  - `AddShadow(RectTransform target)`
  - `CreateDivider(Transform parent, float y)`
  - `CreateAccentTitle(...)`
  - `CreateStyledButton(...)`（Primary/Secondary/Ghost/Danger + ColorBlock）
  - `CreatePill(...)`（准备状态徽章）
  - `CreateCircleBadge(...)`（VS）
- **不改**节点名与 `Bind(...)` 字段名，保证 `BattleLobbyView/BattleRoomView` 代码零改动。
- 新增只重建这三个预制体的菜单：

`Tools/Battle/只重建大厅与选人界面（不动联机预制体）`

> 不调用 `BuildNetworkingPrefab()`，避免再次触发 UnityTransport 脚本绑定问题。

### 4.2 新增修复菜单

`Assets/Game/Scripts/Battle/Lobby/Editor/BattleNetworkingRepair.cs`

- `Tools/Battle/修复联机预制体缺失脚本`：
  1. `AssetDatabase.ImportAsset("Packages/com.unity.netcode.gameobjects/Runtime/Transports/UTP/UnityTransport.cs", ForceUpdate)`
  2. 重新加载 `BattleNetworking.prefab`，用 `GameObjectUtility.GetMonoBehavioursWithMissingScriptCount` 检查
  3. 输出修复前后数量与 `MonoScript.GetClass()`
- 只读检查 + 重导入，不改任何资产内容。

### 4.3 不动的部分

- `BattleNetworkLauncher`、`RoomState`、NGO/UTP 包、`BattleLobbyView/BattleRoomView` 逻辑。
- 邀请面板 `BattleInviteView` / 邀请弹窗 `BattleInvitePopupView`（本期不做）。
- `UIConfig`、`UIType`、图层顺序。

## 附录：实测结论（2026-10-23）

### 创建房间修复

- 根因：嵌入式 NGO 包 `UnityTransport.cs` 的 MonoScript 导入关联失效（`GetClass()` 为 null），
  `BattleNetworking.prefab` 上对应组件被判定为缺失脚本；强制重导入后 `GetClass()` 恢复，
  预制体缺失组件数 **1 → 0**，`StartHost` 正常。
- 已加菜单 `Tools/Battle/修复联机预制体缺失脚本`（重导入 + 缺失组件数检查）。
- Play 实测：点「创建房间」→ `[BattleNetwork] 房间已创建（Host），端口 7777`，
  `BattleRoomView` 正常打开，`BattleNetworkLauncher.HasSession=true`。
- 仍有一条非阻塞警告 `The referenced script on this Behaviour (Game Object '<null>') is missing!`
  在 StartHost 时出现（来自联机预制体依赖的 NetworkPrefabsList/内部预制体，不是 BattleNetworking
  根节点；根节点缺失数为 0），不影响建房、选人、准备与关闭。

### UI 实测

- 大厅 760×500：金色竖条标题、分隔线、三级按钮、页脚「我的 IP / 状态」全部就位；
  主按钮为亮金底 + 深色字，对比清晰；「加入房间」深色底 + 米白字；「邀请好友对战」Ghost。
- 房间：双卡描边 + 投影、预览内井、金环 VS、准备胶囊（未准备→已准备）、英雄卡金边 +
  右上角金色圆点选中标记；选中安比后 3D 预览出现、名称更新。
- 悬浮球：大厅显示；进入房间隐藏（不再压住左上标题/副标题）；退出房间恢复。
- 返回大厅：页脚状态恢复为默认提示（不再误显示「已存在联机会话」）。
- 关闭房间：联机会话销毁；`AnbiPreview` 不再打出「不是本模块实例化」的回收错误
  （UIModelManager 对非池化预览改为直接 Destroy）。

### 已知说明

- 实测过程中 Tuanjie 编辑器在连续多次 Play/录制后出现图形线程崩溃
  （`GfxDeviceD3D11Base::DrawBuffersBatchMode`，伴随大量 `Resource ID out of range`）。
  重启编辑器后复测全部通过；这是编辑器图形状态问题，不是本次 UI 代码导致。
- 选中标记改用程序化金色圆点（`circle` sprite），避免 `✓` 在字体回退链缺字时不可见。
- 按钮/面板染色基底已从深色的 `EntryButton/BarPanel` 换成近白色的
  `Resources/ui/Theme/btn_round.png`、`panel_round.png`，亮金色才不会被乘成暗橄榄色。
