## 0. 结论摘要

1. 引入框架的**组合根 `ModuleHub`**：把散落的全局管理器收敛为"构造 → 按优先级排序 → 依次 Init → 逆序 Dispose"，业务只通过 `GetManager<T>()` 取用。
2. 完整移植框架 **F_Audio 三通道音频系统**（BGM / 环境音 / 特效音），按路径（YooAsset）或直接 AudioClip 播放，带对象池、预算制、可控句柄。
3. 现有 `ActorAudioComponent` **保留为角色音效门面**，内部改为调用 `AudioManager`，对外 API 不变 → 7 处玩法调用点零改动。
4. 删除三份死代码（旧 2D `AudioManager`、`AudioMixerController`、`Compete/sound/` 整份复制），消除"两套音频互相不认识"的现状。
5. 多人对战补**关键音效 ClientRpc 同步**（受击复用现成 `NotifyDamageClientRpc`，技能/挥击新增一条 RPC；脚步不同步）。
6. 音量改由 **Mixer 分组驱动**，`GameSettings` 仍是唯一持久化来源（PlayerPrefs 不动，设置面板 UI 不动）。

已确认的四项决策：

| 决策点 | 选择 |
|---|---|
| 资源后端 | YooAsset 地址加载（`YooAssetService`，与登录界面同一套） |
| Mixer | 改造现有 `NewAudioMixer`，补 Ambience 组 + 4 个暴露参数 |
| 多人音效 | 关键音效 ClientRpc 同步 |
| 模块系统范围 | 只注册 `MonoManager`（帧驱动）+ `AudioManager`，现有 15 个自举单例不动 |

关键语义（必须原样保留）：

- **构造顺序 ≠ 初始化顺序**：构造看重载书写顺序，Init 看优先级（`OrderBy` 稳定排序，同优先级保持书写顺序）。
- 键是**运行时具体类型**（`manager.GetType()`），用接口/基类查不到。
- `ReadyTask` 是唯一启动屏障；失败时 `IsReady` 保持 false 并 `TrySetException`。
- 释放：`managerOrderList` **逆序**、逐个兜异常、最后汇总抛出。

- 句柄防串扰：播放编号单调递增不复用 + 池租借版本核对。
- 预算在**加载资源之前**检查，超限直接返回 `default` 句柄（不加载、不借池、不触发回调）。
- 路径加载的片段由 Lease 释放；外部传入的 AudioClip 由调用方释放。

## 5. 模块系统设计

### 5.1 契约（原样保留）

```csharp
public interface IManagerBase { void Init(); }

[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = false)]
public sealed class ManagerAttribute : Attribute
{
    public int Priority { get; }
    public ManagerAttribute(int priority = 0) => Priority = priority;
}
```

### 5.2 本项目优先级表

| 优先级 | 管理器 | 类型 | 说明 |
|---|---|---|---|
| 1 | `MonoManager` | MonoBehaviour | 帧驱动，音频的 `UpdateAudio` 依赖它 |
| 3 | `AudioManager` | 纯 C# | 音频三通道 |
| （预留） | `VfxManager` / `UIManager` / … | — | 后续迁移时补 `ManagerList.Add` |

### 5.3 注册与释放

```csharp
internal void RegisterAllManagers()
{
    var ManagerList = new List<IManagerBase>();
    var FrameDriver = this.GetOrAddComponent<MonoManager>();
    ManagerList.Add(FrameDriver);
    ManagerList.Add(new AudioManager(audioManagerConfig, transform, FrameDriver));

    foreach (var Manager in ManagerList.OrderBy(GetManagerPriority))
    {
        var ManagerType = Manager.GetType();
        if (managerDict.ContainsKey(ManagerType))
            throw new InvalidOperationException($"[ModuleHub] 重复管理器类型 {ManagerType.FullName}");
        managerDict.Add(ManagerType, Manager);
        managerOrderList.Add(Manager);
    }
}
```

释放：`CleanupFramework` 逆序、逐个 try/catch、汇总 `AggregateException`（不吞异常）。

### 5.4 Bootstrap（新增文件）

```csharp
public static class ModuleHubBootstrap
{
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    private static void AutoBoot() => EnsureAsync().Forget();

    /// <summary>可重复调用；场景里已手摆 FrameRoot 时直接复用</summary>
    public static async UniTask<ModuleHub> EnsureAsync();
}
```

- 场景里已有 `ModuleHub`（手摆调试场景）→ 复用，不重复创建（照 `LoginSceneBootstrap` 的"按组件定位而非按名字"写法）。
- 关掉 Domain Reload 时的静态残留：`EnsureAsync` 先用 `FindFirstObjectByType<ModuleHub>()` 探测。

### 6.3 资源与句柄语义（写入代码注释，避免后人踩坑）

- 路径加载：**一个请求一个 `AssetHandle`**，播完/停止/替换即释放；不建立第二套引用计数。
- 外部 AudioClip：管理器只播放、不接管生命周期，调用方负责。
- 预算超限返回 `default` 句柄 = **拒绝**（不是失败重试）。
- 旧句柄不会操作池里复用后的新声音（编号 + 租借版本双校验）。

### 6.4 预算默认值（与框架一致）

`MaxConcurrentEffects = 32` / `MaxEffectsPerFrame = 10` / `MaxSameClipEffects = 4` / `EffectPrewarmCount = 8`。

## 9. 多人音效同步设计

### 9.1 现状问题

`PlayerComboState` 在 `player.IsRemote` 时直接跳过音频；脚步/受击/闪避全在本地状态机 → 远端角色完全没声音。

### 9.2 方案（实测后修正）

现状核查结论：状态机在**远端镜像端也会跑**（`PlayerComboState` / `PlayerHurtState` 里都有 `if (player.IsRemote)` 分支），所以：

| 音效 | 现状 | 处理 |
|---|---|---|
| 受击 HIT（`PlayerHurtState.Enter`） | **远端本地已经在播**（没有 IsRemote 判断） | **不需要同步**，加 RPC 反而变双声 |
| 闪避 Dodge（`PlayerDashingState.Enter`） | 同上 | **不需要同步** |
| 连招台词 ComboVoice / 武器挥击 WeaponSound | `PlayAttackClip` 在 `IsRemote` 时提前 return → 远端静音 | **新增一条 RPC** |
| 脚步 | 只在本地走步频循环 | **不同步**（频率高、收益低） |

实现（`Player.Audio.cs`，`Player` 改 `partial`，RPC 挂在已有的 NetworkBehaviour 上，不动预制体组件列表）：

```csharp
// 拥有者本地播完 → 广播实际播出的下标
public void BroadcastComboAudio(int comboIndex, int voiceIndex, int weaponIndex)
{
    if (!IsSpawned || IsRemote) return;
    if (voiceIndex < 0 && weaponIndex < 0) return;
    PlayComboAudioClientRpc(comboIndex, voiceIndex, weaponIndex);
}

[ClientRpc]
private void PlayComboAudioClientRpc(int comboIndex, int voiceIndex, int weaponIndex)
{
    if (IsOwner) return;                                    // 自己已本地播过
    var data = ComboStateMachine.ReusableData.currentCombo.GetComboData(comboIndex);
    ActorAudio?.PlayRemoteClip(data.characterVoice, voiceIndex, true);
    ActorAudio?.PlayRemoteClip(data.weaponSound, weaponIndex, false);
}
```

- 为了拿到"实际播出的下标"，`ActorAudioComponent.PlayComboVoice/PlayWeaponSound` 与 `CharacterCombo.PlayCharacterVoice/PlayWeaponSound` 改为**返回 int**（-1 = 没播）。
- 包体约 12 字节/次；4 人混战峰值 ≈ 8 次/秒，可忽略。
- 兜底：`ActorAudio == null`、`currentCombo == null`、下标越界 → 静默跳过。

**仍未验证**：真正的 2 客户端听感（需要 Host + Client 双进程，编辑器只能跑一个 Play 实例），列入 P7。
