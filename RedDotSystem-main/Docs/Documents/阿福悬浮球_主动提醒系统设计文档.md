# 阿福悬浮球 · 主动提醒系统 设计文档

> 版本：v1（已实施并验证）
> 日期：2026-10-17
> 决策记录：悬浮球默认**左上角、可拖动、点击打开阿福面板**；v1 触发范围**只做"邮件附件未领取"**；
> 文案生成**走 LLM（共用 LangGraph 阿福本体）**；作用域**全场景常驻（DontDestroyOnLoad）**。
> 实施修订（2026-10-17 实施后用户追加定稿）：
> ① 巡检/提醒节奏间隔 **3 分钟**（原设计 15 分钟）；
> ② 新增**双击球体彻底隐藏**：本次登录会话不再出现（重登恢复），期间提醒只进阿福面板历史；
> 单击动作延迟 0.3s 执行（给双击留判定窗口）；
> ③ 气泡框两处实施修复：底图改**拉伸锚点铺满**气泡根（原固定 100x100 占位不随文字扩）；
> 量宽改用**常激活隐藏量宽器**——实测 TMP 对 inactive 对象 ForceMeshUpdate 量宽不可靠
> （同段文字 inactive 120 / active 172.8），窄量导致"一字一行"竖排。

## 0. 一句话概述

给游戏加一个**王者"灵宝"式的主动 AI 助手**：屏幕上有一颗阿福头像悬浮球，服务端检测到
"邮箱有附件没领"这类事件时，让**同一个阿福**（共用 LangGraph、共用记忆、共用对话历史）
主动想一句话提醒玩家，推送到客户端后从悬浮球右侧弹出消息框，7 秒自动消失。
一句话总结架构：**一个 Agent、两个用法**——被动问答走 3101（玩家问），主动关怀走 3107（阿福说）。

### 目标
- 玩家不主动提问也能收到阿福的贴心提醒（v1：邮件附件未领取）。
- 提醒文案由 LLM 生成，带阿福人设与玩家已选的说话风格（温和管家/元气伙伴/毒舌损友）。
- 悬浮球全场景常驻，可拖动，位置记忆；点击进入阿福聊天面板继续对话。
- 提醒同时归档进与阿福的对话历史（面板里能看到，玩家还能追问"帮我领了"）。

### 非目标（v1 明确不做）
- 其它触发类提醒（任务可提交/保底临近/好友申请）——协议与管线的 kind 字段已预留，后续接入只是加触发器。
- 消息队列（多条提醒排队逐条展示）——v1 新消息直接顶替当前气泡。
- 点击气泡跳转对应面板（如直接打开邮箱）——气泡不接点击。
- 登录简报（3104）改 LLM——维持现状（确定性模板、零成本），但悬浮球会复用它做登录问好展示。

## 1. 现状盘点（阿福被动链路全景）

```
客户端 AgentPanel(zhuye, agent 画布)
   │  3101 AgentChatRequest（玩家输入）
   ▼
.NET 网关 AgentHandler（限频 10次/分、长度校验、会话身份绑定）
   │  HTTP ndjson 流式转发
   ▼
Python AgentServer :8898（FastAPI + LangGraph 五节点图）
   ├─ ingest → agent ⇄ tools(≤5轮) → respond → critic
   ├─ 记忆：checkpointer(thread=player_{id}) + 滚动摘要 + L3长期记忆 + QA缓存
   ├─ 工具：经 InternalAgentApiServer :8897 回查背包/任务/邮件/抽卡/好友/排行榜
   └─ 归档：append_chat(chat_messages) → 面板历史回放(3105/3106)
   │  3102 终值回执 + 3103 流式分片
   ▼
客户端打字机渲染（AgentUIController + AgentTweenFx）
```

**已有的"主动推送"雏形——3104 登录简报**：登录成功 → .NET `PushLoginBrief` →
Python `/agent/brief` 确定性模板组装（零 LLM 成本）→ 归档 → 推 3104 →
面板开着上屏、关着只做入口按钮脉动。**悬浮球正是把这条"服务端主动 → 客户端展示"的管线
推广成正式通道，并把展示端从"入口脉动"升级成"灵宝气泡"。**

关键复用资产：
| 资产 | 位置 | 悬浮球如何复用 |
|---|---|---|
| LangGraph 阿福本体（人设/风格/记忆/工具） | AgentServer/graph.py、persona.py | `/agent/proactive` 端点直接跑**同一个图、同一个 thread** |
| 对话历史归档 | storage.append_chat | 提醒以 assistant 行归档，面板可见、可追问 |
| 阿福头像/贴图 | Resources/Agent/afu_avatar.png、Agent/ui/* | 悬浮球+气泡运行时 Resources.Load |
| 内部数据 API | InternalAgentApiServer :8897 | 巡检查"未领附件数"复用 BuildMailSummary 同源数据 |
| DOTween 表现层 | AgentTweenFx | 气泡入场/淡出/球体呼吸动画同款 unscaled 约定 |

## 2. 总体设计：一个 Agent 两个用法

```
【被动 · 玩家问阿福】                         【主动 · 阿福找玩家】
玩家输入 ──3101──► 网关 ──HTTP──► LangGraph   事件(邮件到达/巡检未领)
                                          │
                                          ▼
                                    .NET AgentReminderService（频控+并发闸）
                                          │ HTTP /agent/proactive {player_id, kind, data}
                                          ▼
                                    Python：组装事件指令 → 跑同一个 LangGraph
                                    （LLM 生成文案，自动带玩家已选风格；失败→模板兜底）
                                          │ {ok, message, created_ms}
                                          ▼
                                    .NET 推 3107 AgentProactiveNotify
                                          │
             面板开着 → 进面板聊天流 ◄──────┤
             面板关着 → 悬浮球右侧弹气泡 ──► 7 秒自动消失
```

- **同一个虚拟机、同一个 thread_id**：主动提醒在玩家主对话线程上跑——阿福"记得"自己说过什么
  （玩家追问"刚那封邮件是什么"时上下文里有）；归档只记 assistant 行（照 `/agent/brief` 先例），
  面板历史里看到的就是"阿福主动说了一句话"，不会出现"玩家:【系统事件】…"这种怪行。
- **风格自动跟随**：graph 的 agent 节点每轮现读 `get_style(player_id)`——毒舌损友风格的玩家
  收到的提醒就是毒舌口吻（"邮件都要长蘑菇了"），这是"一个 Agent"最直接的收益。
- **身份模型不变**：3107 纯服务端推送，客户端无请求路径；玩家 ID 只来自服务端会话与内部数据，
  客户端无法伪造、无法主动索取提醒。

## 3. 服务端设计

### 3.1 .NET 新增 `Manager/AgentReminderService.cs`

静态服务，Program.cs 启动时 `Start()`（内部起一个后台定时线程），两类触发：

**① 到达触发（邮件带着附件落库）**——挂三个真实发信点：
| 钩子点 | 位置 | 说明 |
|---|---|---|
| GM 发信 | MailHandler.HandleMailGrant（SendMail 成功且 items>0 后） | 收件人在线才提醒 |
| 任务奖励满包转存 | QuestRepository.Submit 的 InsertOverflowMail 提交后 | 玩家最容易"不知道奖励进了邮箱"的场景 |
| 背包满转存 | BagRepository.Grant 的 InsertOverflowMail 提交后 | 同上 |

> 运营公共邮件的"到达"发生在玩家拉列表实例化的瞬间（SyncPublicMails），那一刻玩家正打开邮箱，
> 到达提醒没有意义——v1 对公共邮件只靠巡检兜底。

**② 巡检触发（附件一直没领）**：后台线程每 60s tick 一次，对每个**在线会话**：
- 距上次巡检 ≥ 15 分钟 → 查 `MailRepository.GetMails` 数"未领附件封数"（与 BuildMailSummary 同口径）；
- 有未领附件 且 距上次邮件提醒 ≥ 15 分钟 且 本会话巡检提醒次数 < 2 → 触发一次。

**频控账本（防打扰三道闸，全部常量集中定义）**：
| 闸 | 规则 | 默认值 |
|---|---|---|
| 到达冷却 | 同一玩家两条"到达提醒"至少间隔 | 5 分钟 |
| 巡检间隔/封顶 | 巡检再提醒间隔 / 每次登录会话最多巡检提醒次数（间隔可用 CS_AGENT_REMINDER_SWEEP_SEC / CS_AGENT_REMINDER_GAP_SEC 覆盖供 E2E） | 3 分钟 / 2 次 |
| 全局并发闸 | 全服同时在途的 proactive LLM 调用上限（防百人同刻群发把账单打爆） | 3 个，超发排队 |

状态存 `ConcurrentDictionary<int, PlayerReminderState>`（playerId → {lastRemindMs, sweepCount}），
随会话生灭；环境变量 `CS_AGENT_REMINDER_SWEEP_SEC` 可覆盖巡检间隔（E2E 用）。

**推送**：调 Python `/agent/proactive`（超时 20s）→ 成功则向会话发
`MessageID.AgentProactiveNotify(3107) AgentProactiveNotify {kind, content, created_ms}`；
失败只记日志不推（下轮巡检天然重试）。仅对在线会话生效，全程 `X-Agent-Token` 共享令牌。

### 3.2 Python 新增 `POST /agent/proactive`

```
请求 {player_id, kind, data:{title?, unread, claimable}}     # kind="mail_unclaimed"
响应 {ok, message, created_ms, used_llm}
```

流程（`app.py` 新端点，与 `/agent/brief` 同级）：
1. 按 kind 组装**事件指令**（一条 HumanMessage，前缀【系统主动事件】）：
   "【系统主动事件·服务端注入】主人邮箱收到新邮件《{title}》/邮箱里还有 {claimable} 封带附件没领。
   请以阿福的身份主动提醒主人，一两句话、口语化、不要列清单、不要 markdown。
   事件数据已在消息里，如无必要不要调用工具。"（数据内联，省一次工具轮=省时省钱）
2. 以 `thread_id=player_{id}` 跑**主图**（共用记忆/风格/工具/出口限长/反思）→ 取终值。
   **Phase 14 防护层对齐**：config 注入 `request_id=secrets.token_hex(16)`（与 /agent/chat 同款）——
   即便 LLM 在提醒轮意外调了写工具（如 claim_mail_attachments），guard.py 的幂等/限频/单轮预算
   也全程生效，不会成为绕过防护层的后门。
3. `append_chat` 只归档 assistant 行（与 `/agent/brief` 完全同款）。
4. **模板兜底**：图异常/超时 → 用确定性文案（"主人，邮箱里有附件还没领，记得去看看哦"），
   `used_llm=false`，照样归档照样返回——**提醒永不因 LLM 抖动而丢失**。

### 3.3 协议 `AgentPacket.proto`（build_proto.bat 三端同步）

```proto
message AgentProactiveNotify {
  int32  kind       = 1;   // 1=邮件附件未领取（后续：2任务可提交 3保底临近 4好友申请）
  string content    = 2;   // 阿福口吻的提醒正文（纯文本）
  int64  created_ms = 3;   // 生成时间（UTC 毫秒）
}
// MessageID: AgentProactiveNotify = 3107（3101-3106 已占用，号段注释同步）
```

客户端 `ClientNetworkManager`：+`AgentProactiveNotifyReceived` 事件 + 3107 分发案例；
TestClient `--listen` 增加 3107 打印（服务端 E2E 断言口）。

## 4. 客户端设计

### 4.1 新组件 `Assets/Scripts/Agent/AgentFloatBall.cs`（Bootstrap 单例 + DDOL）

- **画布**：运行时程序化构建 `AfuBallCanvas`（ScreenSpaceCamera + GraphicRaycaster，
  sortingOrder=300：高于 zhuye 全部 HUD(0/10)、fuben 三图(50-53)、大地图(60)、暂停菜单(100)，
  低于 UI 点击粒子(500)与新手引导(600)）。**照 UiFx 先例**：单例自举 + DontDestroyOnLoad，
  相机绑定交 UICameraService 的 1 秒 sweep（跨场景自动重绑 worldCamera，防 DDOL 画布失明）。
- **球体**（64px）：圆形 Mask 内 `afu_avatar`（preserveAspect）+ `afu_ring` 描边 + `afu_glow` 底光；
  待机呼吸动画（scale 1→1.04 循环，unscaled DOTween）；收到消息时球体轻拍一下（同入口脉动手感）。
- **默认位/拖动/记忆**：默认屏幕左上角（边距 28px）；按住球体可拖动（IDragHandler），
  松手钳制在屏幕内；位置存 `PlayerPrefs("afu_ball_pos")`，跨会话记忆。
  > 已知取舍：fuben 左上有 320px 导航小地图，默认位与其重叠——玩家拖一次即永久解决；
  > 若不接受，备选方案是默认下移到 y=-420（避让小地图），实施前可再确认。
- **显隐规则**：未登录（MyPlayerId≤0）隐藏；登录成功即显示（含 LOGIN→zhuye 的短暂过渡，可接受）；
  **zhuye 的 AgentPanel 打开期间隐藏**（面板与球是同一角色，同屏出现会分裂）——
  由 AgentUIController 在开/关面板时通知悬浮球（事件直连，不轮询）。

### 4.2 消息气泡（悬浮球右侧，一段时间自动消失）

- 出现位置默认在**球右侧**（间距 10px）；球被拖到屏幕右半侧时**智能翻转到左侧**（尾随同侧尾巴 `afu_tail_right`）。
  定位遵守项目铁律"角锚配同角 pivot"。
- 结构：圆角深色气泡（`afu_round_md`，#2E333D，与阿福聊天气泡同款）+ TMP 正文（#E0E0E0、15px、
  自动换行，文字区最大宽 300px，按 renderedHeight 撑高——复用好友面板"先量后撑"手法）+ 朝向球的尾巴。
- 生命周期：入场 0.25s（scale 0.85→1 + 淡入）→ 停留 **7s**（常量可调）→ 0.4s 淡出；
  停留期间来新消息 → 直接顶替内容并重置计时（v1 不排队）。
- 全程 unscaled（暂停中照常出现，符合"服务器世界不暂停"的项目暂停语义）；`raycastTarget=false`
  不挡点击。

### 4.3 交互与联动

| 输入/事件 | zhuye | 其它场景（fuben/duihua/LOGIN） |
|---|---|---|
| 点击球体 | 打开 AgentPanel（AgentUIController 暴露 `OpenFromFloatBall()` 公有入口；球体隐藏） | 弹本地提示气泡"主界面才能和我聊天哦"（3s，不发协议） |
| 拖动球体 | 全场景一致：移动+钳制+存档 | 同左 |
| 3107 到达·面板开着 | 进面板聊天流（新行 + 入场动画 + 滚到底，照 3104 现有处理） | —— |
| 3107 到达·面板关着 | 悬浮球弹气泡 + 球体轻拍 | 悬浮球弹气泡（全场景都弹） |
| 3104 登录简报到达 | 面板开着进面板（现状）；关着→**悬浮球弹"上线问好"** + 保留入口脉动 | 悬浮球弹上线问好 |

事件订阅集中在两个现有类：`AgentUIController`（3104/3107 的"面板开着"分支 + 通知球显隐）、
`AgentFloatBall`（3107/3104 的"面板关着"分支）。判断"面板是否开着"以 AgentUIController 暴露的
`IsPanelOpen` 静态查询为准（非 zhuye 场景恒 false → 走球）。

## 5. 失败降级链与安全边界

```
LLM 抖动/超时      → Python 模板兜底（used_llm=false），提醒照发
Python 服务整体不在  → .NET 记日志不推；15 分钟后巡检天然重试（与登录简报同哲学：锦上添花不阻塞主流程）
玩家中途掉线        → 推送目标会话不存在即丢弃；下次登录 3104 简报兜底汇报"有附件没领"
提醒风暴            → 到达冷却 5min + 巡检封顶 2 次/会话 + 全局并发 3 并发闸
```

安全：`/agent/proactive` 纳入现有 `X-Agent-Token` 校验（与全部 /agent/* 同闸）；
仅服务端可触达，无客户端请求面；事件指令中携带的邮件标题来自服务端落库前的 SanitizeText 白名单
（GM/系统方撰写，信任链与现有 claim_mail_attachments 工具一致）；玩家无法触发、无法伪造、无法
用自己的文本污染事件通道。**前置核对**：AgentServer/.env 的 `AGENT_INTERNAL_TOKEN` 与
Server/Config/agent_token.txt 必须一致（不一致时工具回查 8897 会被 401 拒）；
改 Python 后必须重启 AgentServer（run_agent.bat 或
`.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8898`）才生效。

成本账（LLM 生成路线）：单条提醒 ≈ 1 次 LLM 调用（数据内联通常零工具轮；critic 仅在用了
数据工具时评审，本链路一般跳过）。频控封顶后：**单玩家单会话邮件类提醒最多 3 次 LLM 调用**（1 到达 + 2 巡检）。

## 7. E2E 验证方案

**服务端**（TestClient 双开 + 服务端日志）：
1. 到达链：登录 test（--listen 挂着）→ 另一客户端 `--mail` 发带附件邮件 → 断言 3107 到达、
   content 为 LLM 口吻、服务端日志 `Agent 主动提醒` 一行；`--peek`/历史接口确认已归档为 assistant 行。
2. 冷却链：连发两封带附件邮件 → 断言只有 1 条 3107（5 分钟冷却生效）。
3. 巡检链：`CS_AGENT_REMINDER_SWEEP_SEC=10` 启动 → 发一封带附件邮件不领 → 断言 ~10s 后巡检 3107；
   继续不领 → 第 3 次巡检不再提醒（封顶 2 次）；领掉后不再提醒。
4. 兜底链：临时把 LLM 令牌改错（触发图异常）→ 3107 仍是模板文案（used_llm=false 路径）；
   停掉 Python → 无 3107、服务端仅告警日志。
