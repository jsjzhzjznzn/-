# 对话场景存档系统方案（duihua：随时退出、回来还在原处）

> 目标：在 `duihua` 场景里对话到一半退出游戏（或返回主页），下次进入 `duihua` 时回到退出时的位置、朝向、相机与**当前这一句台词**。
> 形态：服务端权威存档（定案 B），对话粒度为「节点」而不是「逐字」。
> 本文档为施工蓝图，实施后按 §9 验收并把实测结论回填 §12。

---

## 0. 结论摘要

1. **当前项目完全没有存档**：对话进度只在内存，位置只在场景文件里，服务端没有一个「玩家状态」表。
2. **原神不是「录屏回放」**，而是把世界状态拆成**有限快照**（场景 + 坐标 + 相机 + 任务步骤/剧情标记），在推进的瞬间就异步落库；对话逐句进度本来就设计成可丢弃（重登重播该段）。
3. 我们按用户定案走**服务端权威**：新增 `player_scene_saves` 表 + 3301–3304 协议，客户端在节点变更/选项/移动节流/暂停/返回主页时上报，进入场景时拉取并重建。
4. 恢复语义按用户定案为**回到当前这句**：恢复到节点级（该句从头打字机播放），并**抑制已选选项的事件重放**，避免叙事任务（2705）被重复推进。
5. 失败一律降级：拉取超时 2s 内走场景默认开局，绝不阻塞加载、不抛异常、不卡对话。

## 1. 现状与证据

### 1.1 对话进度：纯内存，无任何持久化

| 证据 | 位置 |
|---|---|
| ViewModel 只有内存 `runtimeModel`；`StartDialog(graph)` 永远 `GoTo(graph.StartNode)` | `Assets/Game/Narrative/DialogSystem/Scripts/MVVM/ViewModel/DialogueViewModel.cs` |
| 运行时状态 `Graph / Variables / CurrentNode` 无序列化、无落盘 | `.../MVVM/Model/DialogueModel/DialogueRuntimeModel.cs` |
| Runner 只暴露 `StartDialog() / PlayGraph(graph) / GoNext() / SelectOption()`，**没有「从某节点开始」的入口** | `.../MonoRunner/DialogueRunner.cs` |
| 导演只管相机、输入、面对面转向，不写任何状态 | `Assets/Game/Demo/GenshinDialogDirector.cs` |
| 交互入口 `TryStartDialogue` 无「已看过」标记 → 对话可无限从头重播 | 同上 |

### 1.2 玩家位置：只在场景文件里

- `545` 的位置是 `duihua.scene` 的场景摆放值，运行时不写回。
- `DialoguePlayerController` 是 KCC 实现，位置真值在 `KinematicCharacterMotor`（`TransientPosition`），同样不落盘。

### 1.3 服务端：没有玩家状态表

`competeserves/Server/Database/` 现有 14 个仓库（账号/好友/聊天/榜单/背包/任务/邮件/叙事任务/签到/活动/自动登录/副本等），**没有任何位置、场景、对话相关的表**。

最近的相似物是 `mm_player_quests`（叙事任务状态 + 目标进度），它记录的是「任务处于哪个 step」，**不记录对话图跑到哪个节点**。

### 1.4 唯一的本地存档与本需求无关

`Assets/Game/Narrative/QuestSystem/MVVM/Model/QuestSaveData/QuestSaveService.cs` 写 `Application.persistentDataPath/quest_save.json`，只服务 Mm 任务系统的单机 JSON 存档。

### 1.5 当前行为复述

对话中 → 设置 → 返回主页 → 再点「开始冒险」：回到 `duihua` 初始摆位，按 F 从头播第 1 句。**玩家的直观感受就是「没有存档」。**

## 2. 原神是怎么做到「随时退出，再进还是原来的地方」

> 官方未公开实现，以下是其可观察行为推导出的通用做法，用来指导我们的取舍。

### 2.1 存的是「世界状态快照」，不是「画面」

持久化的最小集合：

```
场景ID + 坐标 + 朝向 + 相机朝向 + 任务步骤/剧情flag + 业务数据（背包/抽卡/邮件…）
```

**不存**：字幕打到第几个字、动画第几帧、镜头插值到哪。恢复 = 加载场景后用快照**重建**。

### 2.2 对话本身不存「第几句」

剧情推进是任务状态机：任务当前 step 决定「该播哪段对话」。

- 对话中途退出：任务仍停在原 step（对话不推进 step，选项/整段结束才推进）。
- 重登后：任务回到该 step 的触发点，**这段对话从头再播**。

代价是丢两三句话，收益是存档模型极简且天然幂等——这正是「随时退出」能成立的关键。

### 2.3 保存在事件点，不是「退出时」

任务步骤推进、传送、进出秘境、拾取/开箱、打开菜单、每日重置 → 打脏标记后异步落库 + 定时心跳。

原因很现实：移动端会被系统直接杀进程，`OnApplicationQuit` 不可靠。**只靠「退出时保存」必然丢档**。

### 2.4 边界规则兜底

| 情况 | 原神行为 | 我们的对应 |
|---|---|---|
| 在秘境/副本里退出 | 回秘境入口（副本状态不持久） | `fuben` 不存位置（v1 非目标） |
| 危险区域退出 | 回最近安全点 | 预留（场景边界校验） |
| 断线重连 | 优先拉服务器快照 | 我们同样以服务端为权威 |
| 换设备 | 同一份存档 | 服务端表天然支持 |

### 2.5 一句话

**「随时退出回原处」= 把「原处」定义成小快照 + 在状态变化的那一刻就写进服务器 + 恢复时重建。**
我们按这个模型实现，只把「对话粒度」从任务 step 细化到节点（用户选择：回到当前这句）。

## 3. 目标与非目标

### 3.1 v1 目标（本期）

1. `duihua` 场景的位置 / 朝向 / 相机（yaw、pitch、距离）持久化。
2. 对话进度持久化到**节点级**，恢复后：
   - 对话 UI 打开、相机在正确的正反打机位；
   - 该句台词从头打字机播放；
   - 若停在选项节点，选项列表与原一致；
   - **已选过的选项不重复发布事件**（不重复推进 2705 叙事任务）。
3. 触发点覆盖：节点变更、选项、对话结束、移动节流、打开设置（Esc）、返回主页、应用退出/失焦、断线重连补发。
4. 服务端权威 + 失败降级（超时/无档/节点失效）。

### 3.2 非目标（本期不做）

| 项 | 原因 |
|---|---|
| 逐字/逐帧精确恢复 | 用户已定案节点级；逐字需存打字机进度，收益极低 |
| 副本（`fuben`）位置持久化 | 原神也认为副本地图不持久；等有需求再按同一张表扩展 |
| 登录后直接进入上次场景 | 需要新的启动流程（跨过主页），属产品决策，列为 P4 候选 |
| 多端并发冲突解决 | 单端语义：后写覆盖（可加时间戳拒绝旧快照，见 R2） |
| 反作弊级位置校验 | 位置只影响本机表现，无可交易收益（见 R1） |
| 存档迁移/版本升级框架 | 表加 `save_version` 字段预留，本期只写 1 |

## 5. 数据模型

### 5.1 协议（新增 `SaveStatePacket.proto`，MessageID 3301–3304）

> 号段说明：1001–1005 登录、2xxx 账号/好友/聊天/榜单/背包/任务/邮件、2701–2710 叙事任务、2801–2804 副本、2901–2914 活动、3001–3002 心跳、3101–3107 Agent、3201–3209 对战邀请。**3301 起为空闲段**。

```proto
syntax = "proto3";
package common.network;
option csharp_namespace = "Common.Network";

// 场景存档快照（当前版本只服务带 3D 世界 + 对话的场景）
message SceneSaveSnapshot {
  string scene_name        = 1;   // 场景名（"duihua"），长度 ≤ 64
  float  pos_x             = 2;
  float  pos_y             = 3;
  float  pos_z             = 4;
  float  rot_y             = 5;   // 朝向（绕 Y 轴欧拉角，度）
  float  cam_yaw           = 6;   // 第三人称相机水平角
  float  cam_pitch         = 7;   // 垂直角
  float  cam_distance      = 8;   // 第三人称距离（DialogueCameraZoom）
  bool   dialogue_active   = 9;   // 是否正处在对话中
  string dialogue_graph    = 10;  // 对话图资产名（DialogueGraph_545_Liuying）
  int32  dialogue_node_id  = 11;  // 当前节点 ConfigId（0 = 无）
  string dialogue_vars_json      = 12; // 对话变量快照（预留，见 D4）
  string dialogue_fired_json     = 13; // 本段对话已发布过的 eventKey 列表（防重复推进任务）
  int64  updated_at_ms     = 14;  // 服务端写入时间（回执里填）
}

message SaveStatePullRequest  { string scene_name = 1; }

message SaveStatePullResponse {
  bool   success     = 1;
  string message     = 2;
  bool   has_save    = 3;   // false = 无档（首次进入）
  SceneSaveSnapshot snapshot = 4;
}

message SaveStatePushRequest  { SceneSaveSnapshot snapshot = 1; }

message SaveStatePushResponse {
  bool   success = 1;
  string message = 2;
  int64  server_updated_at_ms = 3;  // 服务端权威时间
}
```

约定：

- **拉取**按 `scene_name` 查询；**上报**一次性覆盖该 `(player, scene)` 行（UPSERT）。
- 身份一律取会话绑定 `session.PlayerId`（与全项目一致），消息体里**没有** `player_id`。
- 上报无推送、无广播（存档是私有数据）。

### 5.2 表（`Migrations/015_AddSceneSaves.sql` + `EnsureTable` 幂等兜底）

```sql
CREATE TABLE IF NOT EXISTS `player_scene_saves` (
  `player_id`             BIGINT       NOT NULL,
  `scene_name`            VARCHAR(64)  NOT NULL,
  `pos_x`                 DOUBLE       NOT NULL DEFAULT 0,
  `pos_y`                 DOUBLE       NOT NULL DEFAULT 0,
  `pos_z`                 DOUBLE       NOT NULL DEFAULT 0,
  `rot_y`                 DOUBLE       NOT NULL DEFAULT 0,
  `cam_yaw`               DOUBLE       NOT NULL DEFAULT 0,
  `cam_pitch`             DOUBLE       NOT NULL DEFAULT 0,
  `cam_distance`          DOUBLE       NOT NULL DEFAULT 0,
  `dialogue_active`       TINYINT      NOT NULL DEFAULT 0,
  `dialogue_graph`        VARCHAR(128) NOT NULL DEFAULT '',
  `dialogue_node_id`      INT          NOT NULL DEFAULT 0,
  `dialogue_vars_json`    TEXT         NULL,
  `dialogue_fired_json`   TEXT         NULL,
  `save_version`          INT          NOT NULL DEFAULT 1,
  `updated_at_ms`         BIGINT       NOT NULL DEFAULT 0,
  PRIMARY KEY (`player_id`, `scene_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 5.3 服务端校验（进库前，失败一律 `success=false` + message）

| 字段 | 规则 |
|---|---|
| `scene_name` | 非空、≤64，**白名单** `{ "duihua" }`（扩展时加） |
| `pos_*` | `float.IsFinite` 且 `|v| ≤ 1000` |
| `rot_y` | 归一化到 `[-180, 180]` |
| `cam_pitch` | `[-89, 89]` |
| `cam_distance` | `0`（未初始化）或 `[1.0, 20.0]` |
| `dialogue_graph` | ≤128 |
| `dialogue_node_id` | `>= 0` 且 `<= 1_000_000` |
| `*_json` | ≤ 8192 字符，非法 JSON 直接丢弃（置空而不是拒整包，保证位置仍能存） |
| 未登录 | `请先登录` |

服务端实现落点：`competeserves/Server/Database/SceneSaveRepository.cs` + `Handler/SceneSaveHandler.cs` + `MessageHandler` 路由 + `Program.cs` 启动 `EnsureTable()`。

### 6.2 自动存档触发点

| 触发 | 落库内容 | 时机 | 备注 |
|---|---|---|---|
| 对话节点变更 | graph + nodeId + active=true | **立即** | 用户最关心的一档；人速级别，量极小 |
| 选项选择 | nodeId + firedEventKeys | 立即（与上一条合并成一笔） | 防重放的关键数据 |
| 对话结束 | active=false, nodeId=0 | 立即 | 结束后 `F` 可重播 |
| 玩家移动/转身 | 位置 + 朝向 | 3s 去抖 + 位移 > 0.25m 或转角 > 5° | 静止不写 |
| 相机转动/缩放 | yaw/pitch/distance | 与位置同批 | 不单独触发写库 |
| 打开设置（Esc） | 全量 | 立即（进入暂停前） | 截图语义的「我此刻在这」 |
| 返回主页 | 全量 | `SceneLoader.LoadAsync` **之前** | 关闭面板后、卸载场景前 |
| 应用退出 / 失焦 | 全量 | `OnApplicationQuit` / `OnApplicationPause(true)` | best-effort，不能依赖 |
| 断线重连 | 最新未发快照 | `LoginResponseReceived` / 重连成功 | 见 D7 |

### 6.3 恢复时序（进入 `duihua`）

```
场景加载完成（Awake/Start 都跑过）
        │
        ├─ DialogueSceneSaveController.Start()
        │       └─ SceneSaveService.Pull("duihua")  ← 2s 超时
        │
        ├─ 无档 / 失败 / 超时 → 保持场景默认（结束，不打扰玩家）
        │
        └─ 有档
              1) motor.SetPositionAndRotation(pos, Euler(0, rotY, 0), bypassInterpolation:true)
                  ├─ 必须在场景加载后、第一帧移动前；KCC 真值在 Motor，不能只改 Transform
                  └─ SetPositionAndRotation 会同步 Transform 与 TransientPosition
              2) 相机：pov.m_HorizontalAxis.Value = cam_yaw
                        pov.m_VerticalAxis.Value  = cam_pitch
                        zoom.SetZoomImmediate(cam_distance)
              3) dialogue_active && nodeId>0
                  └─ director.RestoreDialogue(nodeId)
                        ├─ InputLocked = true
                        ├─ 立刻面对面（不播 0.3s 动画，避免恢复瞬间镜头对不上）
                        ├─ cameraDirector.EnterDialogue(player, npc)
                        └─ runner.PlayGraphFrom(graph, nodeId)
                              └─ ViewModel: BindGraph → 应用存档变量 → GoTo(nodeId)
                                    └─ NodeChanged → View 出 UI（打字机从头）
```

**恢复完成前不开放输入**：`InputLocked` 保持到恢复结束，避免玩家在拉取期间先走两步导致位置被判脏又覆盖存档。

### 6.4 退出与返回主页

- `SettingsView.OnReturnHomeClicked()`：先 `await SceneSaveService.FlushAsync()`（超时 1s，失败不阻塞），再 `UIManager.Close` 与 `SceneLoader.LoadAsync("zhuye")`。
- `OnQuitClicked()`：`FlushAsync()` 后 `Application.Quit()`。**注意**：这是 best-effort；真正的保证来自「事件驱动即时落库」。
- 返回主页后 `duihua` 存档仍在服务端；下次从主页「开始冒险」进入即恢复。

### 6.5 框架改动（最小面）

```csharp
// DialogueRunner
public void PlayGraphFrom(DialogueGraph graph, int nodeId)
{
    dialogueGraph = graph;
    viewModel.StartDialogFrom(dialogueGraph, nodeId);
}

// DialogueViewModel
public void StartDialogFrom(DialogueGraph graph, int nodeId)
{
    runtimeModel.BindGraph(graph);
    var node = graph?.FindNode(nodeId);
    if (node == null) { StartDialog(graph); return; }   // 节点失效 → 降级从头
    GoTo(node);
}

// SelectOption 内（唯一改动点）
if (!string.IsNullOrEmpty(choice.eventKey) && !SuppressEvent(choice.eventKey))
    NarrativeEventBus.NarrytiveBus.Publish(NarrativeEventKeys.DialogueTriggered, graph, choice.eventKey);
```

`FiredEventKeys`：`HashSet<string>`，**恢复时从存档装载**；`SelectOption` 命中即「已发过」→ 跳过发布并从集合移除（同一 key 只抑制一次）。

## 7. 关键设计决策

### D1 服务端权威，但位置由客户端上报

服务端是**存储权威**（唯一真相、跨设备、不可本地篡改文件），不是**表现权威**（位置本身无法在服务端模拟）。
结论：位置/相机不校验（只做范围护栏）；对话节点以客户端上报为准，但事件推进任务仍由 2705 服务端引擎裁决——两条链路互不替代。

### D2 对话粒度 = 节点

恢复的是「当前节点」：该句从头打字机播放。不恢复逐字进度、不恢复打字机计时。
理由：用户定案；原神同思路（丢一句可接受）；实现只差一个 `GoTo(nodeId)`。

### D3 已选选项的事件抑制

`SelectOption` 会 `Publish(DialogueTriggered, graph, eventKey)` → `.NET` 网关转 2705 → 服务端推进叙事任务进度。
恢复后如果玩家在**同一选项节点**重新选同一条，会二次推进任务（进度 +1）。因此：
- 存档携带 `dialogue_fired_json = ["demo_choice_a", ...]`；
- 恢复时装载进 `FiredEventKeys`；命中即不发事件；
- 只在「本段对话」内有效，对话结束清空。

### D4 事实类变量不入档（重新播种）

`BindGraph` 的顺序是 `InitDefaultVariables` → `DialogueFacts.SeedInto`（背包等实时事实覆盖图内默认值）。
若把变量原样存档，`item_477_count` 这类事实会在下次登录时变成**过期值**。
结论：
- 存档里保留 `dialogue_vars_json` 仅作**前向兼容**；
- 恢复顺序调整为 `InitDefaultVariables → 应用存档变量 → SeedInto(事实)`，**实时事实永远最后覆盖**；
- v1 当前图（26 节点）没有任何「设置变量」的节点，所以实际上不会丢东西。

### D5 一玩家一场景一档

主键 `(player_id, scene_name)`，不同场景互不覆盖。`fuben` 以后直接复用，不需要改表。

### D6 失败降级

| 情况 | 行为 |
|---|---|
| 拉取超时（2s）/ 未连接 / 服务端 500 | 场景默认开局，`Debug.LogWarning`，不弹 UI |
| `has_save=false` | 场景默认开局 |
| `dialogue_graph` 资源找不到 / `nodeId` 不在图里 | 位置与相机照常恢复，**跳过对话**，打一条警告 |
| `cam_distance=0` | 用场景默认值 |

### D7 写入节流与合并

- **单飞**：同一时刻最多 1 个 `SaveStatePushRequest` 在途；期间的新快照只更新 `pending`，回执后立刻补发最新（丢中间态，只写最终态——位置场景天然可合并）。
- **去抖**：位置 3s；对话节点变更不参与去抖（立即写）。
- **断线**：发送失败或未连接 → 保留 `pending`；重连/登录成功后补发一次。
- **暂停中也要能发**：存档逻辑全走 `unscaledDeltaTime`/`Task`，不受 `Time.timeScale=0` 影响（`duihua` 打开设置就是 0 倍速）。

### 12.4 fuben 实测结论（未达验收，需单独修）

- 存档链路本身可用：上报成功、回执到达、重进后控制器拿到 `AppliedSnapshot`。
- 但**位置恢复被场景自身覆盖**：fuben 加载完成后玩家就在 `(-60.17, 0.21, -31.53)`（场景文件里存的是 `(0, 0.184, 0)`）；手动把玩家设到 `(5, 0.184, 3)`，下一帧读回 `(-63.50, 0.21, -20.72)`。
- 该位移与存档功能无关（**无存档时同样发生**），判定为 fuben 场景/碰撞或角色初始化的既有问题；在修掉之前 fuben 的位置/相机恢复不会生效。
- 相机：`CM_FreeLook` 的 `m_BindingMode=5`（SimpleFollowWithWorldUp），`m_XAxis.Value` 写入后会被首帧重新播种为 0，`Y` 值可保持。修复需按「首帧后再写轴 / 存真实相机位姿」处理，随 fuben 场景问题一起做。

### 12.5 已知噪音与遗留

- 场景卸载时 DOTween 对已销毁 `CanvasGroup/RectTransform` 的告警（对话 UI 的滑入动画跨场景存活），与存档无关，属既有表现。
- `Application.Quit` 的真实退出路径只做了代码接入（`OnQuitClicked` → Flush），未做进程级验证。
- 断线重连补发只做了代码接入（`LoginResponseReceived` → 补发 pending），未构造断网用例。
- 协议源码目录 `frined/protobuf` 与 `TestClient` 不在 git 仓库内（既有状况），proto 改动未入库，生成的 `.cs` 已在两端仓库。
