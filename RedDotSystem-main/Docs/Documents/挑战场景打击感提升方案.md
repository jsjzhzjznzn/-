## 0. 结论先行

1. **现在没有打击感，不是数值调得不好，是反馈链路断了。**
   - 玩家 4 段平 A 的 `_pauseFrameTime` / `_shakeForce` **全部为 0**（`anbi_ATK1~4.asset`）→ 打中怪没有任何停顿；
   - 命中点没有受击特效：`VfxKeys.EnemyHit` 只在「怪打玩家」「副本小怪」时播，玩家打 BOSS 不播；
   - 命中没有打击音：连招只播 `universalSound`（挥砍），`SoundData` 里 `PARRY`、`WeaponSound` 根本没配；
   - 相机震屏系统不存在：`CharacterCombo` 里的调用被注释（`CameraHitFeel` 类不存在），`tiaozhan.scene` 上的 `CameraShakeManager` 脚本已丢失（正好是那两条 "referenced script (Unknown) is missing" 之一）。
2. **不需要重做战斗，只要把已有钩子接上，再加 3 个高收益机制。**
   P0：接震屏 + 命中特效 + 打击音 + 填顿帧（半天，配置为主）。
   P1：轻重分层、粘刀（命中锁位 + 吸附）、受击闪白/抖动/击退。
   P2：弹刀、极限闪避慢镜、FOV/径向模糊、击杀特写。
3. **顿帧用「局部 + 全局」混合**：轻击只冻结两名角色的动画（不吃操作手感），重击/弹刀才用全局 `timeScale`（沿用现有 `PauseManager` 通道）。

## 1. 参考拆解：打击感到底由什么组成

把视频与文献的观点收敛成本项目可执行的一张表：

| 层 | 手段 | 本项目现状 | 优先级 |
| --- | --- | --- | --- |
| 时间 | 顿帧/卡肉（冻结双方 40~250ms，越重越长） | **完全缺失**（配置为 0） | P0 |
| 时间 | 顿帧期间受击方抖动（振幅递减）、受击动画插入 | 无 | P1 |
| 空间 | 击退/位移（重击推开、弹刀双方后退） | 无（BOSS 有碰撞位移能力可复用） | P1 |
| 镜头 | 震屏（方向随攻击、距离衰减）、FOV 推拉、径向模糊 | **系统缺失** | P0 / P2 |
| 视觉 | 命中点特效、受击闪白/材质变化、武器拖尾 | 仅起手弧光；无命中特效、无闪白 | P0 |
| 听觉 | 挥砍 + 命中 + 低频冲击 三层 | 仅挥砍；无命中/无低频/无弹刀 | P0 |
| UI | 伤害数字（红/暴击橙+弹跳） | **已有**（`DamageTextManager`） | 微调 |
| 交互 | 粘刀：索敌吸附、命中锁位、刃口贴合 | 只有自动索敌旋转 | P1 |
| 交互 | 弹刀：玩家攻击撞上 BOSS 攻击 → 双方弹开 | 无（`SoundStyle.PARRY` 是预留） | P2 |

> 关键判断（来自文献，也是视频的主线）：**顿帧是性价比最高的一项**；但**滥用会毁操作感**（忍龙就几乎不用顿帧）。
> 所以本项目不做「刀刀长停顿」，而是按连招段分三档：轻 50ms / 中 80ms / 重 120ms，只有弹刀与击杀才超过 150ms。

原神 / 鸣潮的体感参照（社区观察与拆解，**非官方精确数值**，只作为方向）：

| | 原神 | 鸣潮 |
| --- | --- | --- |
| 轻击顿帧 | 很短，几乎只冻结双方动画 | 略重，能明显看出"卡一下" |
| 受击反馈 | 怪物闪白 + 元素特效 + 数字克制 | 闪白 + 更强的镜头推拉/低频音 |
| 高光时刻 | 元素爆发、处决 | 弹刀/极限闪避有明显子弹时间与镜头推近 |
| 结论 | 偏"顺滑、可读" | 偏"重量、冲击" |

**本项目的目标区间：介于两者之间偏鸣潮**——BOSS 只有一只、场景是 1v1，可以承受更重的反馈。

## 2. 现状诊断（代码级证据）

| 能力 | 现状 | 证据 |
| --- | --- | --- |
| 玩家命中顿帧 | 机制存在，**数值为 0** | `CharacterCombo.AttackTrigger` → `player.HitStop(data.pauseFrameTime)`；`anbi_ATK1~4.asset` 的 `_pauseFrameTime: 0` |
| 顿帧实现 | 全局 `Time.timeScale = 0.03`，实时期限 | `Player.HitStop()` / `PauseManager.PushHitStop`；倍速写死 `HitStopTimeScale=0.03` |
| 震屏 | **不存在** | `CharacterCombo` 197~199 行调用被注释；全工程无 `CameraHitFeel`；`tiaozhan` 的 `CameraShakeManager` 脚本 guid 找不到 |
| 相机能力 | 已具备 Cinemachine 震动接收端 | `tiaozhan.scene` 的 `thirdcamera` 挂 `CinemachineImpulseListener`；主 `Camera` 有 `CinemachineBrain` |
| 命中特效 | 只有起手弧光 | `CharacterCombo.PlayAttackVFX` → `VfxKeys.PlayerAttackSlash`（绑武器骨骼）；命中点无特效 |
| 命中音效 | 只有挥砍通用音 | `CharacterCombo.PlayComboFX` → `ActorAudio.PlayByStyle(universalSound)`；`SoundData.asset` 只配了 FOOT / HIT / Dodge |
| 受击（BOSS） | 只播受击片段 0.4s | `HurtAction`；无闪白、无抖动、无击退 |
| 受击（玩家） | 有反馈，且比打怪强 | `PlayerHurtState` + `SoundStyle.HIT` + `VfxKeys.EnemyHit` + 0.045s 顿帧（`EnemyBrain.ResolveAttackHit`） |
| 伤害数字 | 已有，普通红 60 / 暴击橙 78 带弹跳 | `DamageTextManager` |
| 粘刀 | 只有索敌旋转 | `CharacterCombo.UpdateAttackLookAtEnemy` + `autoAimStickyBonus` |
| 弹刀 | 未实现（有预留命名） | `SoundStyle.PARRY`、`ComboData._parryName`（注释） |
| 后处理 | 挑战场景没有 Volume | 场景内无 `Volume` / `VolumeProfile` |
| 挑战计时 | 使用 `Time.time`（会被顿帧放慢） | `ChallengeManager.Update` |

**一句话**：玩家打 BOSS 这条链路上，「顿帧、震屏、命中特效、命中音效、闪白、击退」六项全缺；BOSS 打玩家反而有其中三项。这也解释了为什么「挨打有感觉、打人没感觉」。

## 3. 一次命中的时间轴（本项目版）

```
t=0ms    打击帧判定 → 命中成立
         ├ 伤害结算（已有）
         ├ 命中点特效 + 命中音（P0）
         ├ 顿帧开始：双方动画冻结 / 全局压低（P0）
         └ 相机 Impulse 震屏（P0）
t=16ms   受击方受击动画切段、模型抖动（P1）
t=50ms   顿帧结束（轻击），恢复动画/输入
t=60ms   伤害数字飘出（顿帧后才飘，避免数字僵住）
t=80ms   击退位移完成（重击，P1）
t=120ms  受击闪白衰减结束（P1）
t=300ms  连击窗口/后续段
```

关键纪律（文献第 2 条）：**顿帧期间判定位置不能跟着角色移动**，否则原本该中的一刀会 miss。命中点一律取「命中瞬间」的 `Collider` 位置缓存。

## 4. 逐项方案

### 4.1 顿帧（Hit Stop / 卡肉）

#### 三种实现对比

| 方案 | 做法 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| A 全局 | `PauseManager.PushHitStop(scale)`（现有） | 一行接入、逻辑/物理/动画全停，最"实" | 相机、UI、VFX、计时一起慢；长时间会晕 | 重击 / 弹刀 / 击杀 |
| B 局部 | `animancer.Playable.PauseGraph()`（动画图暂停），双方各一份 | 相机/UI 不受影响，手感顺滑 | 动作层计时器照走（判定仍可能推进） | 轻 / 中击 |
| C 只冻结攻方 | 只暂停玩家动画 | 最轻 | 受击方没有"被打中"的停顿感，效果差一半 | 不推荐 |

> 视频里的"修改攻击速度"对应 B 的简化版（改 `Animator.speed`）。用 Animancer 的 `Playable.PauseGraph()` 更干净（`AnimancerPlayable.PauseGraph` / `UnpauseGraph` 实测存在）。

#### 推荐：混合（P0 先做全局，P1 补局部）

| 事件 | 类型 | 时长 | 倍速 / 冻结 | 说明 |
| --- | --- | --- | --- | --- |
| ATK1 轻 | 局部 | 0.05s | `PauseGraph` 双方 | 主要给"刀进去了"的触感 |
| ATK2 轻 | 局部 | 0.06s | 同上 | |
| ATK3 中 | 局部 + 尾 | 0.08s | 同上 + 0.02s 0.6 倍 | 开始有"停顿+缓冲" |
| ATK4 重 | 全局 | 0.12s | `timeScale 0.05` | 终结段要"沉" |
| BOSS 打玩家 | 全局 | 0.07s | `timeScale 0.06` | 现状 0.045s，略加长 |
| 破防（韧性打空） | 全局 | 0.15s | `timeScale 0.04` | 高光 |
| 弹刀 | 全局 | 0.20~0.25s | `timeScale 0.02` | 见 §4.3 |
| 击杀 | 慢镜 | 0.5~0.7s | `timeScale 0.15` | 见 §4.9 |

要求：
- 时长全部**用 realtime 计时**（现有 `Player.HitStop` 已经是 UniTask `ignoreTimeScale`）；
- `Player.HitStop` 的倍速改成参数，不要写死 0.03；
- 连击段之间不叠加超过 2 次，否则手感"粘住"。

#### 实现位置

新增 `Assets/Game/Scripts/Battle/Presentation/HitFeel/HitFeelService.cs`（DDOL 单例）统一入口：

```csharp
HitFeelService.Play(new HitFeelRequest {
    attacker, victim, hitPoint, hitNormal,
    damage, isCritical, isHeavy, comboIndex,
    pauseMs, shakeForce, vfxKey, soundStyle,
});
```

内部依次做：顿帧 → 震屏 → 特效 → 音效 → 闪白 → 击退 → 通知 UI。
这样后续加技能/怪打人都走同一入口，不会又散落回各处。

### 4.2 粘刀（Blade Stick / Attack Magnetism）

分四层，从便宜到贵：

| 层 | 内容 | 现状 | 计划 |
| --- | --- | --- | --- |
| ① 索敌旋转 | 起手时选最近/最正的目标，0.1s 内插值转向 | **已有** | 保持 |
| ② 命中锁位 | 打击帧确定目标后，**锁死这次命中的朝向**，不再被 autoAim 改选 | 无 | P1（`CharacterCombo` 内 5 行） |
| ③ 吸附位移 | 打击帧若目标在 `attackDistance*1.6` 内、且与判定球边缘差 `d`，把攻方沿朝向拉近 `min(d, 0.35m)`，2~3 帧完成，带碰撞 | 无 | P1 |
| ④ 刃口贴合 | 命中特效放在 `targetCollider.ClosestPoint(weaponBonePos)`，并让受击方沿刀方向轻推 0.03m | 无 | P1 |

参数建议：吸附距离上限 0.35m、每帧最多 0.12m、只对「本次打击帧的第一个目标」生效；吸附过程禁止改变 Y。

> 注意：吸附是"让明明差一点点的刀能中"，不是"隔空拉人"。超过 0.35m 就不吸，避免变成磁铁。

### 4.3 弹刀（Deflect / Clash）

#### 触发条件（全部满足）

1. 玩家处于攻击的**打击帧**（`CharacterCombo.ATK()` 被调用）；
2. BOSS 当前动作是 `AttackAction`，且 `NormalizedTime` 落在该招式的 **Active 窗口**（`hitFrames[0]-0.05` ~ `hitFrames[last]+0.05`）；
3. 双方水平距离 ≤ `def.range + 0.6`，且 BOSS 大致面向玩家（夹角 ≤ 90°）；
4. 玩家本次攻击不是 DoT/远程；弹刀冷却 ≥ 1.5s（防连弹）。

#### 表现

```
火花大特效（命中点 + 法线）
金属弹刀音 + 低频"震刀"（SoundStyle.PARRY）
全局顿帧 0.20~0.25s（timeScale 0.02）+ 相机 force 0.85 震屏
玩家后退 0.35m、BOSS 后退 0.45m（用 EnemyBrain.MoveAlong 带碰撞）
BOSS 进入 Stagger 0.6s（复用 StaggerAction），并给 1.2s 韧性回复延迟
玩家不掉血、不进 Hurt（可以接下一段）
```

#### 实现位置

- `EnemyBrain` 暴露 `public AttackAction CurrentAttack`（`controller.Current as AttackAction`）；
- `AttackAction` 加 `public bool IsInActiveWindow`（用 `NormalizedTime` 与 `def.hitFrames` 判定）；
- `CharacterCombo.AttackTrigger` 命中 BOSS 时先问 `HitFeelService.TryDeflect(...)`，成功则**跳过普通伤害结算**（弹刀不加伤害，避免变成最优解）；
- 音效/特效复用 `VfxCatalog` 新增 `deflect_spark`、`SoundStyle.PARRY`。

> 设计取舍：弹刀**不造成伤害**，只换取节奏与 BOSS 硬直；否则"弹刀 = 高伤"会让玩家只练弹刀。

### 4.4 极限闪避慢镜（P2，可选）

项目已有 `E_DamageBlocked`（无敌窗拦截伤害时派发），是天然的触发点：

```
闪避窗内被 BOSS 打中 → 已有 E_DamageBlocked
  → 慢镜 timeScale 0.25 持续 0.35s（realtime）
  → 镜头 FOV -4°、轻微径向模糊、低频音
  → 玩家侧短暂无敌（已有）
```

与已有的 `PauseManager` 叠加规则天然兼容（顿帧通道）。风险是改变战斗节奏，需要你确认是否要。

### 4.5 镜头（震屏 / FOV / 后处理）

#### 震屏（P0，必做）

`thirdcamera` 已经挂了 `CinemachineImpulseListener` → 只缺发射端。

新增 `Assets/Game/Scripts/Battle/Presentation/Camera/CameraHitFeel.cs`（DDOL 单例，同时**替代掉丢失的 `CameraShakeManager`**）：

```csharp
public void CameraShake(float force, Vector3 direction, float duration = 0.15f);
```

- 实现：`CinemachineImpulseSource`（或运行时 `GenerateImpulseWithForce`），按 `force` 与相机距离衰减（文献第 8 条：拉远要增强）；
- 方向和攻击方向一致（水平为主，重击带一点 Y）；
- 参数：轻 0.15 / 中 0.3 / 重 0.55 / 弹刀 0.85；时长 0.08~0.2s；
- 同时把 `CharacterCombo` 里那段注释解开，改用 `CameraHitFeel.MainInstance.CameraShake(data.shakeForce, ...)`。

**顺便清理**：`tiaozhan.scene` 上那个 `CameraShakeManager` 组件的脚本 guid 已经找不到，安装新类后把这个空组件删掉（同时也消掉一条 missing script 报错）。

#### FOV / 推近（P2）

- 重击：FOV 45 → 43，0.08s 回弹；
- 击杀/处决：FOV → 38 并轻微推近，配合慢镜；
- 实现：`CinemachineVirtualCamera.m_Lens.FieldOfView` 的短 Tween（不用改 vcam 结构）。

#### 径向模糊（P2，可选）

挑战场景目前没有 Volume。需要：
1. 场景加 `Global Volume` + Profile；
2. 写一个 URP `ScriptableRendererFeature`（RadialBlur，参数：中心、强度、时长），只在弹刀/极限闪避/击杀的 0.15s 内开启。
   成本较高、且全屏效果容易晕，**建议放到最后**。

### 4.6 受击表现（BOSS 侧）

| 项 | 方案 | 成本 |
| --- | --- | --- |
| 闪白 | 给 `URPGenshinToon.shader` 加 `_HitFlash (0~1)`，在 Forward 片元里向白 lerp；新增 `HitFlash` 组件用 `MaterialPropertyBlock` 在 0.12s 内衰减 | 中（要改 shader，所有用该 shader 的材质会重编） |
| 闪红（退路） | 照 `DungeonEnemy` 的做法改 `_BaseColor` 向红 lerp | 低，但无法变白、效果弱 |
| 受击抖动 | 模型根节点本地偏移 0.03m、0.1s 内衰减（不影响判定） | 低 |
| 击退 | 轻 0 / 中 0.05m / 重 0.15m / 破防 0.35m，`EnemyBrain.MoveAlong(-attackDir)`（带碰撞） | 低 |
| 受击动画 | 已有 `HurtAction`（0.4s）+ `Goblin_Ani_Hit_L_Front` 等片段 | 已具备 |

> 闪白是"打中了"最直观的信号，建议做；如果不想动 shader，就先上闪红 + 抖动 + 击退。

### 4.7 命中特效 / 轨迹

| 项 | 方案 |
| --- | --- |
| 命中点特效 | 复用已有 `VfxKeys.EnemyHit`（P0 零成本），按伤害档缩放 0.6~1.2；P1 再加 `hit_spark_heavy`（可搜特效库） |
| 特效朝向 | 沿攻击方向 + 命中法线，避免永远朝向相机 |
| 武器拖尾 | 现有 `PlayerAttackSlash` 是挂在武器骨骼上的预设特效；P2 再考虑真正的 Trail（需要按刀尖两根骨骼采样） |
| 受击材质 | 见 §4.6 闪白 |

### 4.8 音效

三层结构（P0 最少做前两层）：

| 层 | 内容 | 现状 |
| --- | --- | --- |
| 挥砍 | `universalSound`（已有） | ✅ |
| 命中 | 新增 `SoundStyle.ImpactLight / ImpactHeavy`，随机 ±5% 音高 | ❌ 需补 clip |
| 低频冲击 | 重击/弹刀叠加一层 60~120Hz 的低频"闷响" | ❌ 需补 clip |

实现：`ActorAudio.PlayOneShot3D(clip, volume)` 直接播（不查表也可）；或扩 `SoundData` 的 style 表。
音画同步：命中音效比特效**提前 0~1 帧**触发（音频有输出延迟）。

### 4.9 伤害数字与 HUD（微调）

- 顿帧期间不飘字（等顿帧结束再飘），否则数字会被冻在半空；
- 暴击已有 punch；可加「同一目标 0.4s 内连续命中合并/错位」；
- 击杀瞬间：HUD 数字放大 + 短暂停留（P2）。

### 4.10 击杀特写（P2，可选）

`EnemyBrain` 死亡时：慢镜 0.5s（0.15 倍）+ 相机推近 + 死亡特效 + 低频收尾。挑战场景是竞速，**注意慢镜会让「击杀用时」的观感变长**（计时用 `Time.time`，实际会被放慢）——需要你决定是否要。

### 10.5 本轮踩到的三个坑（后续别再踩）

1. **Cinemachine Impulse 运行时不要用 `Legacy` 类型**：
   `LegacyCreateAndReturnEvent` 依赖 `m_RawSignal` 与 `m_TimeEnvelope.Duration`，运行时 `AddComponent` 出来的定义两者都是空/0，
   直接返回 null → 表现是"调了 ShakeCount+1，但镜头一动不动"。改用 `ImpulseTypes.Uniform` + `Bump` 才生效。
   另：力度是**相机位移（米）**，要把 0~1 的"力度"乘一个 ≈0.08 的系数，否则 0.55 会让镜头跳半米。
2. **`MaterialPropertyBlock` 在本项目对 `_HitFlash` 不生效**（URP + SRP Batcher，属性不在材质已有属性表里）：
   实测 MPB 读回 1、渲染像素完全没变；改成 `renderer.materials`（材质实例）后立刻正常。
   BOSS 只有 3 个 Renderer，克隆成本可忽略；`HitReaction` 在 Awake 缓存实例数组。
3. **Shader 属性上的 `[Header(...)]` / `[Tooltip(...)]` 不能带空格或中文**：
   `[Header(Hit Reaction)]` 会让 Tuanjie 的 shader 解析器报 `Parse error: unexpected $undefined`，
   整个 shader 变 `isSupported=False`（材质直接失效）。用 `[Header(HitReaction)]` + 普通 `//` 注释即可。

另外：Tuanjie 里 `ScreenCapture` / 回读 backbuffer 在 URP 下拿到的是**恒定灰**（1920x1080 每点都是 0.804），
像素级验证要"把相机渲到 RenderTexture 再 ReadPixels"，否则会误判"闪白没生效"。

### 10.9 受击改为「连续受击状态」（2026-10-24，取代分层抖动）

用户要求：不要受击暂停感；打中就把怪切到受击状态；一直打就一直受击。

- 轻击 / 重击都进 `HurtAction`（不再走 Layer 1 上半身抖动）
- 连打时 `HurtAction.Refresh()` 只重置计时、**不重播片段**；片段播完手动 wrap `NormalizedTime` 继续循环 → 受击期间动作一直在动，不会停在最后一帧
- 轻击片段 `Hit_Shake`（0.42s），受击时长 `flinchSeconds = 0.8s`（略大于玩家出刀间隔，连打不断档）
- 重击片段按方向 `Hit_L_Front` / `Hit_L_Back`，0.9s、1.8×
- 破防仍走 `Debuff_Stun_Start`
- **取消判定帧霸体**：任何阶段被打都进受击
- **取消玩家打怪的顿帧**：`HitFeelProfile.hitStopOnPlayerHit = false`（震屏 / 特效 / 音效 / 闪白 / 击退保留）

实测：

```

B 0.3s 后再打: action=Hurt nt 0.80 -> 0.82（继续增长，不回到 0）
C 连打 8 刀: 一直处于 Hurt（中途破防转 Stagger），从未回到 Attack
D 重击: Hurt + 方向片段
```

调参：
- `EnemyProfile.flinchSeconds`：受击尾巴（越大越不容易断档，也越像木桩）
- `HitFeelProfile.hitStopOnPlayerHit`：想恢复顿帧改 true
- `EnemyProfile.heavyHitDamage`：多重算重击
