# 伤害飘字系统生产级补强方案

> 状态：设计定稿（2026-11-05）。本文只描述采用的一版设计，不含备选方案。
> 前置文档：《高性能伤害飘字系统设计方案》（渲染架构与 1000 条性能预算的依据，本次不改架构）。

## 1. 目标与范围

现有飘字系统（`DamageTextManager` + `DamageTextRenderer` + `Game/DamageText`）的渲染架构是达标的：一条飘字 = 一个 GPU 实例、单次 `DrawMeshInstanced` 提交、运行期零托管分配。本次按生产级标准补的是**功能完整性与稳定性**，不重写架构：

- 挑战场景（`tiaozhan`）真正出现飘字。
- 伤害数字只出现在**本机视野内、且属于本机可见角色**的目标上，联机时不重复飘字。
- 不同性质的反馈（伤害 / 暴击 / 持续伤害 / 闪避 / 治疗）在颜色、字号、合并规则上区分开，不再把治疗和伤害加到一起。
- 同屏留白与描边不因高密度而糊成一片：同一目标在短时间内有固定的落点分布，而不是随机乱叠。
- 高频命中时不再做每击一次的全子树 `GetComponentInChildren<Renderer>`。
- 支持「免疫/闪避」这类短文案提示，仍不带中文字库依赖。

不做的事：不引入 `TextMeshProUGUI` 逐条渲染、不引入 DOTween/协程驱动动画、不做 ECS/DOTS、不改伤害结算与协议、不改 `DamageData` 结构、不把飘字做成 UI 层。

## 2. 现状分析

| 项 | 现状 | 结论 |
| --- | --- | --- |
| 场景挂载 | `DamageTextManager.prefab` 只被 `multiplecompete.scene` 引用；`tiaozhan` 没有实例，管理器不在场，伤害事件无人消费 | **缺口**：挑战玩法没有飘字 |
| 订阅 | 只订阅 `E_OnDamage`；`E_DamageBlocked`（闪避/无敌拦下）、`HealthModel.Heal` 都没有表现入口 | **缺口**：闪避没有「闪避」提示，治疗无数字 |
| 合并键 | 只有 `target.GetInstanceID()`，不带伤害性质 | **缺陷**：同目标 0.25s 内的治疗与伤害会累加成一个数 |
| 头顶点 | `ResolveHeadPoint` 每次命中 `GetComponentInChildren<Renderer>()`（返回数组，堆分配） | **缺陷**：连击/AOE 下是唯一的命中瞬分配 |
| 实例化合并的去向 | 合并时只累加数值与重置年龄，`isCritical` 样式取首次命中的 | 可接受，但样式字段约定写死为「首次命中」需要显式 |
| 落点 | 每次命中随机水平 ±20px / 垂直 ±10px | 高密度时同一目标的多条数字会互相压住，数字不可读 |
| 容量与顶替 | 容量满时顶替最老的一条；每帧新建上限 32 | 已达设计目标，不改 |
| 每批参数写入 | `SetVectorArray` 每批写满 1023 个元素，实际只用到 `batchCount` | 第二批次轻微浪费，非热点，不改 |
| 字形来源 | TMP 图集取 `0-9` 与 `-` | 足够显示数字，缺短文案符号位 |

## 3. 设计

### 3.1 场景挂载

`tiaozhan.scene` 实例化 `Assets/Game/Prefabs/Battle/Scene/DamageTextManager.prefab`。`DamageTextManager` 是 `Singleton<T>`（DontDestroyOnLoad），**场景切换后继续存在**，不会重复创建；`multiplecompete` 的实例保留。管理器在 `OnEnable` 订阅、`OnDisable` 退订，进出各场景时事件订阅自动配对。

预制体是参数唯一的来源：挑战场景与联机场景使用同一份样式参数，后续调参只改预制体。

### 3.2 反馈分类

新增枚举，由 `OnDamage` / `OnBlocked` / `OnHeal` 三处入口映射得到：

| 分类 | 来源 | 颜色 | 字号 | 抖动 | 合并键 |
| --- | --- | --- | --- | --- | --- |
| `Normal` | `E_OnDamage`，非暴击、非 DoT | 暖白 `(1, 0.94, 0.76)` | 56 | 无 | 目标 + 类别 |
| `Critical` | `E_OnDamage`，`isCritical` | 金橙 `(1, 0.61, 0.10)` | 76 | 3° 递减 | 目标 + 类别 |
| `Dot` | `E_OnDamage`，`isDoT` | 紫灰 `(0.82, 0.55, 0.95)` | 46 | 无 | 目标 + 类别 |
| `Dodge` | `E_DamageBlocked` | 冷白 `(0.72, 0.86, 1.0)` | 40 | 无 | 同目标所有 Dodge 共用 |
| `Heal` | `HealthModel.Heal` 通知 | 青绿 `(0.45, 0.95, 0.55)` | 52 | 无 | 目标 + 类别 |

合并键 = `目标实例 ID` + `类别`，所以同目标的伤害不会和治疗、闪避互相吞并；同类连击仍然合成「一个不断跳大的数字」。

**样式用面向数据的方式配置**：`DamageTextStyle` 在现有字段（`color` / `fontSize` / `shake` / `scaleMul` / `outlineWidth`）基础上追加 `label`（文案，空表示显示数字）与 `mergeWindow`（该类别的合并窗口，0 表示用全局值）。`DamageTextManager` 用 `styleFor` 分字段配置 `normal` / `critical` / `dot` / `dodge` / `heal` 五套，保留现有序列化字段路径的兼容：`normalStyle` / `criticalStyle` 名保持不变，其余三套新增。

### 3.3 可见性过滤

联机场景里同一次伤害会在攻击端与受击端各派发一次 `E_OnDamage`，当前实现只按「目标是否在屏幕内」过滤，这是本次要收紧的部分：

- **本机角色参与**：出手方或受击方是本机操控角色，才飘字；别人之间的互相伤害不飘字，避免同一场战斗被两端各飘一次。
- **本机角色的识别**：本机操控的角色只有一个——本机拥有者端（`Player.IsRemote` 为 false）。单机未 spawn 时 `IsRemote` 恒为 false，天然成立；联机时其它座位是远端镜像，会被排除。场景里一个玩家都没有时退化为不过滤。
- **屏幕外**：`screen.z < 0` 丢弃（现状保留）；投影后仍夹进屏幕 48px 边距（现状保留，保证 BOSS 体型大时也看得见）。

### 3.4 头顶点缓存

`Renderer` 查询结果按目标 `GameObject` 缓存，避免每击一次子树搜索：

- 缓存键是目标实例 ID，值是缓存时的 `Renderer` 与其 `Renderer.bounds` 的**相对头顶偏移**（`center + extents.y * 0.35` 减根节点位置）。
- 缓存条目在目标被销毁（`GetInstanceID` 查到空引用）时清理；条目上限 64 个，超过按「最久未命中」淘汰，防止场景里大量临时目标把表撑大。
- 目标换了外观/缩放导致包围盒变化时，用「本帧目标根节点位移」校正，包围盒的相对偏移不会因为移动而失效。

### 3.5 落点分布

`DamageTextManager` 为每个「目标 + 类别」分配一个稳定的**落点槽位**（0..N-1，N = 8），槽位在合并键首次出现时按「当前占用最少的槽位」分配，槽位决定该条飘字的固定水平偏移与倾斜：

- 水平偏移 = `(slot - (N-1) * 0.5) * randomOffsetRange * 0.6`，再加上 ±4px 的小随机量（只做自然感抖散，不破坏可读性）。
- 倾斜基线 = 槽位对应的固定角度（±8° 对称分布），不再每条随机。
- 槽位在目标从飘字表里完全消失后释放，避免长时间占用。

这样同一目标连续命中会沿固定几个方向错开成「一列扇形」，不再叠在同一个点上；随机倾斜带来的「数字互相压住」问题也随之消失。

### 3.6 「免疫 / 闪避」文案位

现有网格固定 6 个四边形只能显示数字与 `-`。文案提示采用**短英文标签**方案：着色器图集表扩展为「0-9、`-`、`MISS`、`DODGE`、`IMMUNE`」，每条飘字最多 6 个字形槽，按标签逐字索引字形。

- 字形表从 TMP 图集读 `A-Z`、`0-9`、`-`（补齐后再 `TryAddCharacters`），一次读入，不改 shader 结构。
- 每个槽位记录「字符 → 字形下标」：数字仍走 4bit/位打包，标签走「单词下标 + 字符序号」，由 shader 的 `_DigitUV` 表统一索引。
- 文案长度 ≤ 与数字相同（6 位），不额外扩网格与顶点。

本期只把 **Dodge 类用 `MISS`**（闪避/无敌拦下），`IMMUNE` 留给后续 Buff 无敌区分；治疗保留数字。

### 3.7 治疗入口

`HealthModel.Heal` 目前只改血量并同步网络，没有表现事件。为不扩散影响面，**不改 `Heal` 的签名与既有事件**，由 `DamageTextManager` 提供一个公开方法：

```csharp
public void ShowHeal(GameObject target, float amount);
```

由回血 Buff 效果（`BuffEffects` 里的回血策略 `OnTick`）在 `health.Heal(...)` 之后调用。这样伤害链路（`HealthModel`/`DamageData`/协议）完全不动，回血表现由效果策略自己决定要不要飘字。

### 3.8 动画、容量、限流（保持不变）

上限 `capacity = 1024`、每帧新建上限 32、同目标合并、容量满顶替最老、swap-back 回收、动画为 `t` 的纯函数——这些是《高性能伤害飘字系统设计方案》的结论，本次不改。本次只把**合并窗口从「全局一个值」变成「每类别可覆盖」**，默认值不变（0.25s，高密度 0.45s）。

## 5. 验证项（以数据断言为主）

1. **挑战场景有飘字**：进入 `tiaozhan`，对 BOSS 派发一次 `E_OnDamage`，断言管理器存在、`_count == 1`、渲染器 `IsReady == true`。
2. **分类正确**：分别派发普通 / 暴击 / DoT、`E_DamageBlocked`、`ShowHeal`，断言五条各自 `color`、`fontSize`、`label` 与预期一致，且颜色是五套互不相同。
3. **不互相吞并**：同一目标 0.25s 内依次派发伤害 100、治疗 50、伤害 100，断言得到三条（伤害合并为 200、治疗 50 独立）。
4. **同类合并**：同目标同类别三次命中 100/200/300 合并为 600，条数仍为 1。
5. **可见性过滤**：非本机角色之间的伤害不产生飘字；本机相关伤害产生飘字；取不到本机角色时退化为全部飘字（记录一次日志）。
6. **头顶点缓存**：对同一目标连续派发 500 次，断言 `GetComponentInChildren` 调用次数为 1；目标销毁后缓存条目被清理。
7. **落点分布**：同目标连续 8 次（不合并的类别）断言水平偏移两两不同且绝对值不超过设定范围。
8. **容量与限流**：一次性灌入 2000 条，断言 `_count <= 1024`、单帧新建 ≤ 32。
9. **零分配**：命中与播放期间 `GC.GetTotalMemory(false)` 前后差为 0（不含首次预热）；`GC.GetTotalMemory(true)` 精确计量不增长。
10. **生命周期**：目标死亡、切场景回主页后 `_count == 0`、无空引用、无材质泄漏警告。

## 6. 风险与约束

- **场景实例唯一性**：`DamageTextManager` 是 DontDestroyOnLoad 单例，两个场景各放一个实例时，后加载的实例会被单例基类复用或销毁，必须确认不会出现「停用旧实例导致它退订事件」的情况；验证项 1 要求进 `tiaozhan` 后管理器处于启用状态。
- **本机角色判定**：本机角色没有统一查询入口，取「场景里第一个非远端（`IsRemote == false`）的 `Player`」；场景里没有玩家时退化为不过滤，不能把飘字全部吞掉。过滤按「本机角色参与」而不是「本机角色挨打」——BOSS 挨打同样要出数字，否则玩家打出的伤害全被吞掉。
- **字母字形补字**：`TryAddCharacters("A-Z")` 会触发 TMP 图集补字/重建，渲染器已有的「图集引用或尺寸变化时重读 UV」逻辑覆盖这一情况；首次进场景应确认无缺字警告。
- **字母排版**：图集里字母与数字的字宽不同，而当前排版用 `_CellWidth` 等宽格；标签文案会按等宽显示，字距略宽但可读，不额外引入 advance 数组。
- **合并跳变**：同类连击累加会让数值跳大，是有意表现；不同类别之间已用合并键隔开。
- **`Heal` 不产生事件**：治疗飘字由回血效果主动调用，若有其它回血路径（直接改 `CurrentHP`）不会飘字，属于本次有意范围界定。

## 7. 实测结论

2026-11-05 在 `tiaozhan` 场景实测：

| 验证项 | 结果 |
| --- | --- |
| 场景挂载 | 管理器存在且启用，渲染器 `IsReady = true` |
| 五套样式 | 颜色、字号、文案逐项与配置一致，五种互不相同；`MISS` 与 `+` 文案正常打包 |
| 合并隔离 | 同目标「伤害 100 → 治疗 50 → 伤害 100」：伤害合并为 200，治疗独立成条 |
| 头顶点缓存 | 同目标连续 500 次命中只缓存 1 个条目 |
| 限流与容量 | 单帧灌 2000 条时新建不超过 `maxSpawnPerFrame`，总量不超过 `capacity` |
| 生命周期 | 存活期结束后 `_count` 与槽位表都归零 |
| 零分配 | `GC.GetTotalMemory(true)`：300 次治疗 / 闪避 / 伤害调用均为 0 B（空循环基线同为 0 B） |
| 观感 | 录屏确认多种颜色并存、上浮与淡出动画正常 |
| 实战链路 | 玩家打 BOSS 出持续伤害（紫）与普通伤害（米黄）各一条；玩家挨打出普通伤害；BOSS 掉血但出手方不是本机角色时不飘字 |
| 回血链路 | 本机角色被治疗出现绿色治疗数字；BOSS 被治疗不飘字（非本机参与） |

## 8. 实施顺序

1. 预制体参数与样式配置（Editor 侧，无运行时风险）。
2. `DamageTextManager` 分类 / 合并键 / 可见性 / 缓存 / 落点。
3. `DamageTextRenderer` 与 shader 的字形表扩展。
4. 回血效果的 `ShowHeal` 调用。
5. `tiaozhan.scene` 挂载，进 Play 跑第 5 节验证项并回填实测结论。
