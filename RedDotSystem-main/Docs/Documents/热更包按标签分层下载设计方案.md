# 热更包按标签分层下载设计方案

## 1. 现状

ui 热更包（YooAsset Package `ui`）承载 UI 预制体、UIConfig、Lua 脚本、物品图标与活动内容。发布 1.1.4 实测 308 个 bundle / 81.85MB，构成如下：

| 内容 | 收集组 | 体积 | 占比 |
|---|---|---|---|
| 活动内容 `Assets/Content/HotContent` | ActivityContent | 45.20 MB | 55% |
| UI 预制体与图片 `Assets/Game/UI` | GameUI | 5.83 MB | 7% |
| 图标与图集 `Assets/Game/Resources/ui` | ItemIcons | 11.85 MB | 14% |
| 字体（NotoSansSC SDF / MapleMono） | 依赖带入 | 22.2 MB | 27% |

玩家首次登录必须等整个包下载完才能进入主页，不玩活动的玩家也要承担 45MB 的活动内容。

**不能拆成独立 Package**：两个包会各自打一份同名共享依赖（`unityshaders.bundle`、TMP 字体 bundle），Unity 不允许同时加载内容不同但内部同名的 AssetBundle。因此活动内容与 UI 必须留在同一个 YooAsset 包内。

## 2. 设计

单包 + 资源标签分层下载：

- 收集器按业务设 `AssetTags`：`GameUI`、`LuaScripts`、`ItemIcons` 为 `base`；`ActivityContent` 为 `activity`。
- YooAsset 打包时把资源标签写入 manifest，并沿依赖关系传播（被 base 与 activity 共同引用的共享 bundle 会同时带两个标签，因此任一侧下载都能拿到）。
- 登录后 `YooAssetService.UpdatePackageAsync` 只用 `ResourceDownloaderOptions(BaseTag, …)` 创建下载器，只补齐基础内容。
- 进入活动时 `LuaActivityHost` 用 `ResourceDownloaderOptions(ActivityTag, …)` 补齐活动内容，下载期间由 `ActivityLoadingTip` 显示百分比。

常量定义：

- `YooAssetService.BaseTag = "base"`
- `LuaActivityHost.ActivityTag = "activity"`
- `LuaActivityHost.DownloadProgress`（0~1，-1 表示无下载）供加载提示读取。

### 2.1 登录不再预热活动资源

`ActivityShell.OnLoginResponse` 不再调用资源包预热。预热会把 45MB 活动内容在登录阶段下完，使标签分层失去意义；改为进入活动时按需下载并显示进度。

### 2.2 不做整包清缓存

bundle 文件名为内容哈希（`FileNameStyle = HashName`），内容变化必然换名，旧 bundle 留在沙箱不影响加载。整包清缓存会把登录时已下好的 base 内容一并删掉，因此活动宿主只做「版本 → manifest → 按标签下载」，不再调用 `ClearCacheAsync`。

## 3. 影响面

- 收集配置：`Assets/BundleCollectorSetting.asset`（ui 包四个收集器加标签）。
- 客户端代码：`YooAssetService`、`LuaActivityHost`、`ActivityShell`、`ActivityLoadingTip`。
- 协议与服务端：无改动。
- 打包流程：无需新增发布流水线，ui 包仍由 `UiPackagePublisher` 发布到 `competeserves/HotContent/ui`；`activity` 与 `battle` 两个空包保持不使用。

## 4. 验收

发布 1.1.4 后实测：

| 场景 | 结果 |
|---|---|
| 登录（全新客户端，缓存清空） | 下 246 个文件 / 38,424,601 字节（36.64MB）；缓存最终 495 个文件 / 36.71MB |
| 登录后主页 | UI 注册表重建 26 项、引导进度就绪、世界频道预热正常 |
| 点击活动入口 | 下 62 个文件 / 47,396,822 字节（45.20MB）；文案 `活动加载中… 0% → 14% → … → 100%` |
| 活动面板 | 打开成功（签到、方舟卡牌均正常），资源包阶段耗时 0.81s（本机） |
| 二次进入活动 | 「资源已是最新，无需下载」，资源包阶段 0.01s |

构建报告对照（1.1.4）：`base` 246 个 / 36.64MB，`activity` 62 个 / 45.20MB，无未打标签的 bundle。

## 5. 风险与边界

- 公网带宽下首次进入活动需下载 45.20MB，已有百分比提示；不玩活动的玩家不再承担这部分体积。
- 活动内容的更新依赖进入活动时的版本检查与标签下载；登录阶段的版本检查只覆盖 base，不会顺带拉取活动内容。
- `EditorSimulate` 模式（`UseHostPlayMode=false`）不受标签影响，全部内容直接走 AssetDatabase。
