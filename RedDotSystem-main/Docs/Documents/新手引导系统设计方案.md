# 主页新手引导设计方案（v2：全功能讲解 + 服务端断点续玩）

> 编写日期：2026-10-27（2026-10-28 追加 §12 左侧任务追踪面板、§13 数字键切角色，见 §14 对步骤表的影响）
> 定位：把已有的 3 步试玩型引导，补成「讲完主页全部入口 + 任何时刻退出都能从原步骤继续」。
> 技术底座：沿用现有 `GuideManager` 的遮罩挖洞框架（`GuideMask.shader` + `GuideMaskGraphic`），不换实现。
> 状态：§1–§11 已落地并实测（见 §11）；§12–§14 为 2026-10-28 追加需求，**仅方案，尚未实施**。

| 文件 | 作用 |

| `Assets/Game/Scripts/Guide/GuideManager.cs` | 引导状态机：自举单例、触发判定、步骤协程、画布构建、结算清理 |

现有能力：遮罩挖洞、洞内点击穿透、气泡跟洞自动上下翻转、跳过、目标解析超时兜底（不会硬卡死）、编辑器 F9 强制重跑。

### 1.2 缺口

| 缺口 | 代码事实 | 后果 |
|---|---|---|
| **没有断点续玩** | 只在结束时写 `PlayerPrefs["guide_done_<id>"] = 1` | 走到第 5 步退出，下次从第 0 步重来 |
| **只讲了 3 个功能** | `GuideSteps.Zhuye` 只有 好友 / 背包 / 任务 | 主页 14 个入口里 11 个没解释 |
| **只能点进去学** | 现有 `Kind.Button` 必须点击真实按钮才推进 | 想「只讲解不打断」做不到 |
| **老号看不到** | 触发条件 `MyPlayerId > 39` 且无完成标记 | 存量账号永远不会出现引导，也没有重看入口 |
| **服务端没有账本** | 无 `player_guide*` 表、无 36xx 协议 | 换机/换号进度丢失；清缓存即重置 |
| **阿福球会盖住引导** | AfuBall 独立画布 `sortingOrder = 5900`，引导画布是 600 | 引导全屏暗罩被悬浮球戳出一个亮洞 |

## 2. 设计目标

> 新账号首次进主页，自动从右下主按钮开始，逐个高亮 14 个入口讲清作用；任何时刻退出，下次登录从同一步继续；老账号在设置里可以重看。

三条硬要求：

1. **逐步存盘**：每推进一格就落库，不是只在结束时记一个"完成"。
2. **不打断操作**：讲解步只高亮、不放行点击，玩家不会误开面板。
3. **布局改动不破**：目标按 `HomeView` 的字段名解析，不写死 transform 路径。

## 4. 交互设计

### 4.1 三种步骤类型

| 类型 | 视觉 | 输入 | 推进方式 |
|---|---|---|---|
| `Info` | 全屏暗罩 + 居中气泡 | 全屏拦截 | 点「开始 / 完成」 |
| `Explain`（新增） | 挖洞高亮目标 + 气泡贴洞 + 「下一步」 | **洞内也拦截** | 点「下一步」 |
| `Skip` | 右下角「跳过引导」全程可见 | — | 立即置完成 |

`Explain` 是这次的核心改动：沿用现有挖洞与气泡定位逻辑，但把 `GuideMaskGraphic` 的命中改成「`blockAll = true`」——遮罩照常画洞，射线却全屏命中，玩家点高亮按钮不会打开面板。

### 4.2 目标解析（不再写死路径）

现有步骤用 `画布根名 + transform.Find 路径`，主页按钮在 `HomeView` 预制体内部，路径一改就失效。

新做法：`GuideStep` 增加 `homeField` 字段（如 `"bagButton"`），运行时：

```
UIManager 取打开的 HomeView 实例 → 反射读同名字段（Button） → 取它的 RectTransform
```

字段被删/改名时走现有 3 秒超时兜底：警告并跳过该步，不会卡死。

### 4.3 视觉

- 沿用现有配色：深色气泡 `#262B33F5`、金色描边、绿色继续按钮。
- 气泡固定在洞口外侧（上/下自动翻转），箭头指向洞。
- 进度提示：气泡标题右侧显示 `3 / 14`，让玩家知道还剩多少。
- **画布层级**：引导画布 `sortingOrder` 由 600 提到 **6000**（阿福球 5900 之上），并在引导期间临时隐藏阿福悬浮球，避免暗罩被戳出亮洞。

### 4.4 退出与恢复

- 玩家在任何一步杀掉进程 → 下次登录进主页，从同一步继续（含气泡文案与高亮目标）。
- 「跳过」与「完成」等价：都写 `completed = 1`，之后不再自动触发。

## 5. 进度存档（服务端权威）

### 5.1 表

`019_AddGuideProgress.sql`：

```sql
CREATE TABLE IF NOT EXISTS `player_guide_progress` (
  `player_id`     INT         NOT NULL COMMENT '玩家ID = accounts.Id',
  `guide_key`     VARCHAR(32) NOT NULL COMMENT '引导标识，当前仅 zhuye',
  `step`          INT         NOT NULL DEFAULT 0 COMMENT '下一次要播放的步骤下标（0=从头）',
  `completed`     TINYINT     NOT NULL DEFAULT 0 COMMENT '1=已完成或已跳过，不再自动触发',
  `updated_at_ms` BIGINT      NOT NULL DEFAULT 0 COMMENT '服务端写入时间（Unix 毫秒）',
  `save_version`  INT         NOT NULL DEFAULT 1 COMMENT '结构版本',
  PRIMARY KEY (`player_id`, `guide_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='新手引导进度（一玩家一引导一行，UPSERT 覆盖）';
```

`guide_key` 让以后新增引导（例如战斗教学）复用同一张表。

### 5.2 协议（`GuidePacket.proto`，3601–3604）

| 消息 | 字段 |
|---|---|
| `GuidePullRequest` 3601 | `guide_key` |
| `GuidePullResponse` 3602 | `success, message, has_record, step, completed` |
| `GuidePushRequest` 3603 | `guide_key, step, completed` |
| `GuidePushResponse` 3604 | `success, message, step, completed, server_updated_at_ms` |

- 身份一律取 `session.PlayerId`，消息体不带玩家 ID（与 3301–3304 一致）。
- 写入是覆盖式 UPSERT，`step` 只接受 `0..步骤总数`，越界钳制。

### 5.3 触发与续播规则

进入 `zhuye` 且已登录后拉取一次（延迟 0.8s 等布局）：

| 服务端记录 | 玩家 | 行为 |
|---|---|---|
| `completed = 1` | 任意 | 不自动开场 |
| `completed = 0` 且 `step > 0` | 任意 | 从 `step` 续播 |
| 无记录，`playerId > 39` | 新号 | 从 0 开场 |
| 无记录，`playerId ≤ 39` | 老号 | 不自动（设置里可手动重看） |

`playerId > 39` 沿用现有分界线常量（当前已知最大 ID 为 39），以后只改这一个常量。

### 5.4 写入时机

| 时机 | 写入 |
|---|---|
| 每步推进（点「下一步」/信息步「继续」） | `step = 当前下标 + 1` |
| 点「跳过」 | `completed = 1` |
| 最后一步「完成」 | `completed = 1, step = 步骤总数` |
| 设置里「重看新手引导」 | `step = 0, completed = 0`，随后本地开场 |

### 5.5 离线兜底

- 拉取失败（未连服/超时）：读本地缓存 `PlayerPrefs["guide_cache_<id>_<key>"]`，续播不阻塞。
- 上报失败：只写本地缓存，下次登录以服务端为准；**服务端无记录而本地有缓存时，用本地缓存续播并立即回写一次**，避免"断网走完、联网后重来"。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 服务端没起，引导卡住或重来 | 本地缓存兜底 + 拉取失败直接走缓存；上报失败静默重试一次 |
| 主页改版导致字段改名 | 按字段名解析 + 3 秒超时跳过，最坏情况少讲一步而不是卡死 |
| 重看时 `completed` 归 0，中途退出会续播 | 有意行为，写进文案（开场气泡已说明"下次从你停下的地方继续"） |
| 阿福球（5900）盖住引导 | 引导画布提到 6000，并在开场时隐藏球、结束时恢复 |
| 引导期间切场景（玩家从别处跳转） | 沿用现有 `sceneLoaded` 处理：视为完成并清理画布 |
| 账号并发（同号双端） | 覆盖式 UPSERT，后写生效；步进只影响体验，不做冲突检测 |
| 存档行被清空导致老号重新触发 | `completed` 丢失时按"无记录 + ID 分界线"处理，老号仍不自动开场 |

### 11.2 实测结果

| 项 | 结果 |
|---|---|
| 服务端启动 | 日志出现「新手引导系统就绪（player_guide_progress 进度表）」 |
| 拉取 | 客户端日志「进度就绪：来源=服务端 有记录=False step=0」 |
| 断点续玩 | 走到第 3 步后杀进程重登 → 日志「[引导] 开始（玩家ID 1，从第 3 步）」；点下一步后 `step 3→4` |
| 跳过 | `savedStep=16 completed=True`，DB `step=16 completed=1` |
| 重看 | 设置里按钮绑定成功（`replayBound=True`）→ 从第 0 步开始，`saved=0 completed=0`，DB 同步为 `0/0` |
| 讲解步视觉 | 挖洞与「好友」圆钮对齐，气泡在其下方、箭头指向按钮，标题显示「好友 3 / 14」 |

### 11.3 与设计的偏差

| 项 | 说明 |
|---|---|
| 中文字体 | 首轮实测引导文本全是方块：TMP 默认字体 LiberationSans 没有中文字形。改为从场景里已有 UI 借能显示「中」的字体（NotoSansSC），不再写死资产路径 |
| 阿福悬浮球 | 画布提到 6000 后已盖住 5900 的悬浮球，实测无穿透，因此没有额外做「引导期间隐藏」 |
| 拉取超时 | 由 1.5s 放宽到 3s（同一会话前面排着 6 个请求、Mongo 还在 2s 超时），并补了迟到响应兜底的订阅 |

## 13. 追加需求 B：数字键 1–4 切换角色（Shader 渐隐渐显）（2026-10-28）

> 需求原话：「按 1234 等数字可以切换角色；切换角色就用显隐性吧，就是 a 角色你用 shader 操作一下让慢慢消失，然后让 b 慢慢出现」。
> 键位约定：**1–4 固定四个键**（预留到 4 人队），候选角色来自 `BattleHeroCatalog`，当前只有安比（`0`）/艾莲（`1`）两个，按到不存在的下标不响应。

### 13.1 现状与缺口

| 项 | 现状（已核实） |
|---|---|
| 角色表 | `BattleHeroCatalog`：`Anbi = 0`、`Ellen = 1`，`Count => Heroes.Length`（当前 2），`HeroInfo` 带 `PreviewPath`（`"Battle/Heroes/AnbiPreview"` / `"Battle/Heroes/EllenPreview"`）、`PortraitPath`、`PreviewOffsetY`、`PreviewOrthSize` |
| 切角色入口 | 只有 `CharacterView`：左右箭头 → `SwitchCharacter(±1)`（首尾循环）、头像行点击 → `SelectCharacter(charId)`；**没有键盘入口** |
| 切换表现 | `LoadPreview` 先 `UnloadPreview()`（销毁旧模型实例 + `UnLoadModelByRawImage`）再 `Instantiate` 新模型 → **硬切，一帧换人**，没有任何过渡 |
| 预览渲染 | `UIRenderToTexture` + 每 `RawImage` 一个 RTT 相机；`Targets` 是 `Dictionary<int, Target>`，**同一张 RawImage 可同时挂多个模型**（相机一次都渲染）；`UIModelManager.LoadModelToRawImage(GameObject, RawImage, …)` 这个重载**不会**先卸载已有模型（只有 `string path` 重载会） |
| Shader | 工程内**没有**任何溶解/淡出 shader（`Assets/Game/Shaders` 只有 `GuideMask.shader`）；角色材质用的是 `URPGenshinToon`（`ThirdParty/Plugins/Shader/二次元/UnityGenshinToonShader-main`）与 URP Lit |
| 键盘先例 | `DialogueView.cs:139` 用 `Input.GetKeyDown(KeyCode.Alpha1 + i)` 选对话选项（旧 Input Manager，工程未启用新 Input System 的独占模式） |

缺口：没有键位、没有过渡、也没有「同一屏两个角色」的渲染路径。

### 13.2 交互设计

| 项 | 决定 |
|---|---|
| 生效范围 | `CharacterView` 打开期间（角色页是全屏面板，主页与其它页面不响应，避免和对话选项、热键抢键）；子面板（武器选择 `PickerRoot`、确认框 `ConfirmRoot`）打开时不响应 |
| 键位 | `Alpha1`–`Alpha4` 与小键盘 `Keypad1`–`Keypad4`，映射 `charId = 键号 - 1`；`charId >= BattleHeroCatalog.Count` 直接忽略（3/4 键现在无反应，加角色后自动生效） |
| 同角色 | 按到当前角色直接 return，不重播动画 |
| 过渡时长 | 淡出 0.28s + 淡入 0.32s，**重叠 0.12s**（总 0.48s），避免出现空帧 |
| 连按 | 过渡中再按：只记录最后一个 `pendingCharId`，过渡结束后立即接上，不排队、不叠加 |
| 提示 | 复用角色页已有的 `hintText`（底部 14px 灰字，现在写的是「拖动模型可旋转视角」），改成「拖动可旋转 · `1` 安比 / `2` 艾莲」，按 `BattleHeroCatalog` 动态拼接；不做背包/属性页专属提示。键位说明不单独占引导步，由「角色」那一步的正文带一句 |

### 13.3 表现：双模型 + 溶解 shader 交叉淡化

不做 alpha 混合（透明排序会把头发/裙摆画穿），走**噪声阈值裁剪（dissolve）**：每个像素按噪声与阈值比较决定是否丢弃，天然对不透明 toon 材质友好，也不需要改渲染队列。

```
时间轴（一次切换）：
t=0.00  旧模型 dissolve = 0（完整）   新模型 dissolve = 1（完全裁掉，不可见）
t=0.28  旧模型 dissolve = 1（完全裁掉） 新模型 dissolve ≈ 0.43
t=0.48  旧模型已销毁                   新模型 dissolve = 0（完整）
```

| 层 | 做法 |
|---|---|
| Shader | 新增 `Assets/Game/Shaders/Character/CharacterDissolve.shader`（`Shader "Game/CharacterDissolve"`）：以 `URPGenshinToon` 为底（保留主光/阴影/描边），新增 `_DissolveAmount`(0=完整,1=消失)、`_DissolveSoftness`、`_DissolveEdgeColor`、`_DissolveEdgeWidth`；片元里 `clip(noise - _DissolveAmount)`，边缘按差值算一圈发光（暖金色 `#E8B45C`，与主页金色描边同族） |
| 材质 | 新增 `CharacterFadeMaterials` 工具：`Instantiate` 模型后遍历 `Renderer`，用 `new Material(original)` → `shader = Shader.Find("Game/CharacterDissolve")` → `CopyPropertiesFromMaterial` 拷回贴图/颜色/关键字；材质实例缓存在当前模型上，模型销毁时一并销毁 |
| 驱动 | 新增 `CharacterFadeController`：`FadeOut(duration)` / `FadeIn(duration)` / `CrossFade(next, inDur, outDur, overlap)`，内部用 `Update` 累加 `Time.unscaledDeltaTime`（角色页可能处在暂停态），逐帧 `SetFloat("_DissolveAmount", t)` |
| 渲染 | 两个模型都用 `UIModelManager.LoadModelToRawImage(GameObject, RawImage, …)` 挂到**同一个** `previewRaw`（同一 RTT 相机、同一挂点位置，靠 dissolve 区分可见性）；新模型 `canDrag=false`，过渡结束后把旧的从 `Targets` 里摘掉并 `Destroy` |
| 兜底 | `Shader.Find` 返回 null 或材质丢失（打成粉红）时，走回退分支：直接 `UnloadPreview + LoadPreview` 老路径（硬切），保证功能不坏、只在 Console 记一条 warning |

**不做**：主页右侧立绘（`HomeCharacterArt`）的同步切换 —— 它是单张静态 Sprite，`BattleHeroCatalog` 里没有「按 charId 的立绘」字段，本轮不新增美术资源；等有立绘表再复用同一套 `CharacterFadeController`（UI 版改成对 `Image` 材质做 dissolve）。

| 文件 | 改动 |
|---|---|
| `Assets/Game/Shaders/Character/CharacterDissolve.shader` | 新增（URP + toon 底 + `_DissolveAmount`） |
