# 方舟卡牌活动接入方案

## 1. 目标

把已移植进 `Assets/ThirdParty/ArkCards` 的《方舟卡牌》接成正式游戏里的一个活动：

1. 活动中心侧栏多一条「方舟卡牌」，点进去右侧显示标题 / 描述 / 「进入活动」按钮。
2. 点「进入活动」收起活动与主页界面，走统一加载条切到 ArkCards 的 `MainMenuScene`（它的主页开始界面）。
3. ArkCards 主菜单左上角有「退出活动」按钮，点击回到 `zhuye`。

## 2. 现状

- 活动中心侧栏条目来自服务端下发的 `ActivityInfo` 列表（`ActivityShell.CurrentActivities`），Lua（`Assets/Content/HotContent/lua/activity_main.lua.txt`）按下标逐条建按钮，按 `type` 分派页面：`1 = 唤取`、`2 = 签到`、`3 = 迷雾信标`。
- 「迷雾信标」是现成的「本地小游戏活动」范例：Lua 里程序化建页面 + 「开始」按钮，点击调 `CS.Game.MiniGame.MiniGameBridge.EnterFogHunt()`；C# 侧 `MiniGameBridge` 负责关 `ActivityView` / `HomeView`，再 `SceneLoader.LoadAsync("fog_hunt")`（自带加载条与防重入）。
- ArkCards 是独立程序集 `ArkCards`，不能引用本工程预定义程序集（`SceneLoader` / `UIManager` 都在 `Assembly-CSharp` 里）；反过来 `Assembly-CSharp` 可以引用 `ArkCards`。
- `zhuye` 场景加载后由场景内的 `HomeViewLauncher` 打开 `HomeView`，因此回主页不需要额外做界面管理。

## 3. 设计

### 3.1 活动条目（客户端本地常驻）

`ActivityShell.ApplyActivityState` 在拿到服务端列表后，追加一条本地条目：

| 字段 | 值 |
| --- | --- |
| ActivityId | 9001 |
| Type | 4（方舟卡牌） |
| BannerId | 0 |
| Title | 方舟卡牌 |
| Subtitle | 明日方舟主题回合制卡牌对战 |
| ContentKey / ContentVersion | arkcards / 内置 |
| StartAtMs / EndAtMs | 0（不参与倒计时） |

追加在末尾，所以「第一个活动」的兼容语义（唤取的 `CurrentBannerId` 等）不变；按下标去重，服务端即使日后下发同 id 也不会重复。条目只影响侧栏与页面，不参与服务端任何计算。

### 3.2 活动页面（Lua）

`activity_main.lua.txt` 增加 `buildArkCardsPage()` / `showArkCardsPage(active)`，与迷雾信标页同构：右侧描述文案 + 「进入活动」按钮 + 状态提示。`selectActivity` 里 `type == 4` 分支收起唤取页 / 签到页 / 迷雾页，顶栏倒计时改显示「长期开放」（本地条目没有时间窗，避免显示「剩余 0 秒」）。

按钮逻辑：

```lua
local ok = CS.Game.MiniGame.ArkCardsActivityBridge.EnterArkCards()
if ok then toast("正在进入方舟卡牌", 1.5)
else toast("暂时无法进入（加载中）", 2) end
```

该类型不走 XLua 代码生成（与 `MiniGameBridge` 一致，走反射调用），避免多一轮 Gen。

### 3.3 进入活动（C#）

新增 `Assets/Game/Scripts/MiniGame/ArkCardsActivityBridge.cs`（`Game.MiniGame`），与 `MiniGameBridge` 同款：

- `EnterArkCards()`：`SceneLoader.IsLoading` 时返回 false；否则关闭 `UIType.ActivityView`、`UIType.HomeView`，`SceneLoader.LoadAsync("MainMenuScene")`。
- 不做次数限制（卡牌是常驻玩法，不是每日限次小游戏）。

### 3.4 退出活动（C# 两侧解耦）

ArkCards 程序集不认识本工程的场景加载链路，所以用事件解耦：

- ArkCards 侧新增 `ArkCards/ArkCardsExitBridge.cs`：`public static event Action ExitRequested` + `RequestExit()`；有订阅者就交给宿主处理，没有就回退 `SceneManager.LoadScene("zhuye")`。
- 本工程侧 `ArkCardsActivityBridge` 用 `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` 订阅 `ExitRequested` → `SceneLoader.LoadAsync("zhuye")`（加载前先退订再订阅，避免重复）。
- 按钮做进 ArkCards 自己的主菜单：`MainMenuUI.BuildUI()` 左上角加「退出活动」（200×64，角锚点左上 + 同角 pivot，避让标题），点击调 `ArkCardsExitBridge.RequestExit()`。

| 文件 | 动作 |

| `Assets/Game/Scripts/Activity/ActivityShell.cs` | `ApplyActivityState` 追加本地条目 |
| `Assets/Content/HotContent/lua/activity_main.lua.txt` | 新增 type 4 页面与分派 |

不改服务端、协议、Build Settings（三个 ArkCards 场景上一轮已入表）。

## 5. 热更

活动 Lua 属于热更内容，正式环境要「Tools/活动热更/构建并发布活动包」把新 Lua 发到 `../competeserves/HotContent`；编辑器内 `EditorSimulate` 模式直接用 `Assets/Content/HotContent`，改完 refresh 即生效。

## 6. 验收

1. 编译零错误。
2. `MainMenuScene` 出现「退出活动」按钮，点击后回到 `zhuye` 且主页界面重新打开。
3. 登录进 `zhuye` → 打开活动中心 → 侧栏出现「方舟卡牌」（排最后）→ 右侧显示描述与「进入活动」→ 点击后加载条切到 `MainMenuScene`。
4. 活动面板关闭后无残留：进入 ArkCards 场景时看不到活动面板与主页界面。

## 7. 风险

- 活动面板打开依赖服务端活动列表回执（未登录/服务端未启动时打不开），本地条目只在拿到列表后才会被渲染——这是既有链路的约束，不另开局部分支。
- ArkCards 是独立程序集，只能通过事件与本工程通信；若日后删除 `ArkCardsExitBridge` 的订阅注册，退出按钮会退回 `SceneManager.LoadScene`（无加载条，仍可用）。
- 本地活动 id 9001 为约定值，服务端若启用同号活动需要调整。

## 8. 实施与实测

已按上述设计落地，并发布活动热更包 `1.3.3`（`competeserves/HotContent`，10 个补丁文件，版本指针 `activity.version → 1.3.3`）。

| 项 | 结果 |
| --- | --- |
| 编译 | 客户端 0 error（5 条 warning 均为既有代码） |
| 活动列表 | 服务端 3 个活动 + 本地条目 = 4 个：长刃唤取·苍鳞、签到、迷雾信标、方舟卡牌 |
| 活动页 | 选中「方舟卡牌」进 type=4 页，顶栏「长期开放」、副标题、描述与「进入活动」按钮正常渲染（截图核对） |
| 进入 | 点「进入活动」→ 加载条 → `MainMenuScene`；活动面板与主页界面均已收起，无残留遮挡 |
| 退出 | 卡牌主菜单左上角「退出活动」→ 加载条 → `zhuye`，主页界面（开始冒险等入口）已重新打开 |
| 字体 | 活动中心所有 TMP 文本此前因 `TMP Settings` 的 `m_fallbackFontAssets` 为空而显示成方块，已把 `NotoSansSC-Regular SDF` 加回全局回退；实测整页无缺字警告、无方块 |

退出按钮的位置与尺寸：左上角 200×64（锚点与 pivot 均为左上，偏移 40,-40）。
